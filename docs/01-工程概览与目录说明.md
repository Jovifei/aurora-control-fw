# 01 · 工程概览与目录说明

## 1. 产品与硬件边界

当前硬件是单路异步 Boost：只有低侧储能 MOS 的 `GLC` PWM，放能依靠并联二极管；不存在同步整流互补PWM，也不存在电池电流传感器。电池电流由 `PV_U × PV_I × 效率 / BAT_U` 估算，并始终带 `ESTIMATED` 质量标记。

默认高功率BOM，通过 `AURORA_POWER_PROFILE` 可切换低功率BOM。两种功率档共用同一套业务代码，不能复制两套状态机。

## 2. 清理后的唯一目录

```text
app/       9个纯业务模块
service/   1个主循环/中断桥接实现 + 1个公共头文件
board/     板级常量、标定和功率门禁
driver/    8个目标驱动 + 1个统一接口头，全部扁平
vendor/    目标构建所需芯片库层
project/   Keil AC6工程、main、interrupts和scatter
docs/      编号文档及原理图，不放.c/.h/JSON
tests/     Host模拟驱动与回归测试，不进目标镜像
tools/     自动门禁，不进目标镜像
```

以下目录已经删除且不得恢复：

```text
firmware/
tasks/
legacy_reference/
legacy_parity/
legacy_protocol_import/
app/中的arm_*厂商文件
firmware/docs中的JSON
重复的firmware/tests与firmware/tools
```

## 3. 为什么保留tests和tools

它们不是产品固件文件，却是必要的工程资产：

- `tests/`验证算法、协议、Flash记录、预充起步、温度故障隔离、DMA覆盖和看门狗健康窗口；
- `tools/`检查目录、依赖、PinMap、PWM preload、Break极性、旧代码回流，并运行GCC/Clang和目标端语法检查；
- Keil工程清单只包含 `app/service/driver/board/vendor/project`，不会把tests/tools链接进MCU镜像。

`tasks/`只属于临时过程管理，对固件交付没有价值，因此已经删除。
