# 01 · 工程概览与目录说明

## 1. 产品与硬件边界

当前硬件是单路异步Boost：只有低侧储能MOS的 `GLC` PWM，放能依靠并联二极管；不存在同步整流互补PWM，也不存在独立电池电流传感器。电池电流由 `PV_U × PV_I × 效率 / BAT_U` 估算，并始终带 `ESTIMATED` 质量标记。

默认高功率BOM，通过 `AURORA_POWER_PROFILE` 可切换低功率BOM。两种功率档共用同一套业务代码，不能复制两套状态机。

## 2. 唯一目录

```text
app/
├─ inc/      9个业务模块公共头、统一类型和应用参数
└─ src/      9个业务模块实现
service/     主循环、ISR事件邮箱与APP↔Driver桥接
driver/      8个目标驱动和1个统一接口头，保持扁平
board/       PinMap、ADC标定、Flash地址和人工安全门禁
vendor/      目标构建所需芯片库
project/     Keil AC6工程、main、interrupts和scatter
docs/        文档与原理图，不放生产.c/.h/JSON
tests/       Host模拟驱动与回归测试，不进目标镜像
tools/       架构、代码规范、编译、Sanitizer和目标语法门禁
```

以下内容已经删除且不得恢复：

```text
firmware/
tasks/
.bootstrap/
legacy_reference/
legacy_parity/
legacy_protocol_import/
app/中的arm_*厂商文件
生成JSON
重复的tests/tools/docs
```

## 3. APP功能模块

| 模块 | 主要职责 |
|---|---|
| app | 调度编排、能量累计、设置切换和协议命令落地 |
| measurement | DMA完整块去极值、标定、物理量快照、BAT_I估算 |
| mppt | Voc初始化、P-V斜率搜索、Vref PI和理论功率请求 |
| charger | 12组档案及TC/CC/CV/Float状态机 |
| protection | 阈值、去抖、active/latched和安全epoch |
| power_stage | 电池识别、预充、继电器、Duty执行器和故障恢复 |
| ui | RUN/FAULT指示相位 |
| protocol | 旧产品UART线格式兼容 |
| storage | 双页Flash Journal、CRC和Commit Marker |

## 4. 为什么保留tests和tools

- `tests/`验证算法、协议、Flash、预充起步、故障重授权、温度隔离、DMA覆盖和看门狗健康窗口；
- `tools/`阻止APP越层、错误PinMap、PWM多出口、运行期软件UPDATE、缺函数头注释、Tab、迟到static、旧源码回流，并运行GCC/Clang/Sanitizer/目标语法检查；
- Keil工程只编译 `app/src`、`service`、`driver`、`board`、`vendor` 和 `project`，不会把tests/tools链接进MCU镜像。
