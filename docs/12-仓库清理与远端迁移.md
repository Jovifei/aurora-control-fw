# 12 · 仓库清理与远端迁移

## 1. 推荐名称

推荐远端仓库名：

```text
aurora-control-fw
```

它不在仓库名中暴露拓扑、功率档或芯片型号。芯片型号仍必须保留在Keil Device、Vendor文件名和编译宏中，否则工程无法构建；“仓库名隐藏”不能等同于“源码中删除器件标识”。

## 2. 为什么不能只在旧目录里移动

旧提交包含多套tests/tools、`firmware/docs`生成JSON、旧MCU完整源码、历史协议导入、应用目录里的厂商`arm_*`文件和大量重复文件。逐个移动很容易把旧依赖继续带进新工程。应使用本清理包整体替换工作树。

## 3. 普通迁移：保留历史

```powershell
cd D:\work\原仓库目录
git status
# 确认没有未提交内容，备份后删除除.git之外的旧工作树
# 将本清理包全部内容复制到仓库根目录
python tools\check_architecture.py
python tools\run_checks.py
git add -A
git commit -m "refactor: rebuild clean embedded firmware layout"
# GitHub Settings中改名后：
git remote set-url origin https://github.com/Jovifei/aurora-control-fw.git
git push origin main
```

这种方式保留旧Git历史，因此历史提交、旧文件名和旧仓库名仍可被找到。

## 4. 严格迁移：远端也不保留旧关键词

严格要求下，最可靠的方式是新建一个空的私有仓库`aurora-control-fw`，只提交本清理包，然后在确认无遗漏后删除旧仓库。仅“Rename repository”或在原仓库强推孤儿分支，都不能保证GitHub缓存、fork、PR引用和旧对象立即消失。

新仓库首提交建议：

```powershell
git init
git branch -M main
git add .
git commit -m "Initial clean firmware baseline"
git remote add origin https://github.com/Jovifei/aurora-control-fw.git
git push -u origin main
```
