# 46 · 300W 新工程分阶段移植与板级验证路线

> **用途**：本文件不是“当前工程怎么运行”的说明，而是后续建立一个**新的、从最小系统开始逐级 Bring-up 的 300W 工程**时的执行手册。
>
> **执行原则**：每次只引入一种新的硬件能力或新的能量风险；上一阶段没有形成可重复的板级证据，不进入下一阶段。
>
> **参考基线**：当前 v0.10.3 候选实现、`docs/11-Keil编译与台架验收.md`、`docs/13-硬件引脚与外设绑定.md`、`docs/35-v0.9.0-BST_U量程风险与硬件整改门禁.md`。
>
> **重要边界**：当前 300W 板是**单路异步 Boost**。PA15/GLC 是当前主 PWM；PA14/GHC 在当前硬件中不作为同步 MOS PWM，必须保持安全低电平。不要把旧 120W 的 Q5/Q6 互补 PWM、死区、DCM/CCM 同步整流逻辑机械移植到新板。
>
> **OTA / IAP**：当前产品决策为**不移植**，不属于本路线任何 Gate 的前置条件。

## 0. 如何使用这份文档

这份路线把迁移分成 16 个 Gate：

```text
G0  硬件/原理图/BOM/PinMap 冻结
 ↓
G1  最小工程 + 上电绝对安全态
 ↓
G2  弱光供电资格 + 时钟 + 1ms节拍 + UART + 看门狗
 ↓
G3  ADC 单通道原始码验证
 ↓
G4  ADC 定时触发 + 六通道扫描 + DMA
 ↓
G5  电压/电流/NTC 工程量换算与标定
 ↓
G6  单路 PWM 无功率验证
 ↓
G7  门极驱动 + COMP + Break 硬件保护链验证
 ↓
G8  低压限流固定 Duty Boost
 ↓
G9  BST_U 预升压 + Relay 安全闭合
 ↓
G10 完整保护矩阵与故障恢复
 ↓
G11 基础闭环 + 限功率 + MPPT
 ↓
G12 TC/CC/CV/Float/Recharge 充电状态机
 ↓
G13 Flash + 协议 + LED + 长时间运行
 ↓
G14 Demo 无电池带载模式
 ↓
G15 5W → 30W → 100W → 额定功率逐级放大
```

### 0.1 Gate 的硬性规则

每一级都必须同时满足：

```text
[代码完成]
+
[Keil 编译通过]
+
[对应 Host/静态测试通过]
+
[实板验证通过]
+
[测试记录归档]
=
允许进入下一 Gate
```

只要其中一项没有证据，本 Gate 状态只能是：

```text
IN_PROGRESS
或
BLOCKED
```

不能写成 `PASS`。

### 0.2 每个 Gate 都必须留下的证据

建议每个 Gate 建立一个目录：

```text
docs/bringup/Gxx-名称/
├─ README.md               本阶段记录
├─ scope.png/svg           接线/测点图，可选
├─ scope-001.png           示波器截图
├─ scope-002.png
├─ meter-data.csv          标定数据，可选
└─ RESULT.md               最终判定
```

至少记录：

| 字段 | 必须填写 |
|---|---|
| PCB 版本 | 例如 C300_MPPT Boost V0.1 |
| BOM 版本 | 关键器件是否替换 |
| 固件 Commit | 精确 SHA |
| Keil/ARMCLANG 版本 | 可复现构建 |
| 仪器型号 | 电源、DMM、示波器、探头、负载 |
| 测试日期 | 年月日 |
| 环境温度 | 模拟标定和热测试尤其重要 |
| 供电设置 | 电压、限流 |
| 负载设置 | 电压/电流/电阻/功率 |
| 测试步骤 | 必须可复现 |
| 理论值 | 公式或预期 |
| 实测值 | 原始证据 |
| 判定 | PASS / FAIL / BLOCKED |
| 遗留问题 | 进入下一 Gate 前必须明确 |

# 1. 总体安全策略

## 1.1 每次只增加一种风险

整个 Bring-up 顺序遵循：

```text
先证明 MCU 能安全活着
→ 再证明“看得准”
→ 再证明“能发对 PWM”
→ 再证明“硬件能自行关断”
→ 最后才允许功率级真正传能
```

严禁下面这种一次性移植：

```text
ADC + PWM + COMP + MPPT + Charger + Relay + Flash
全部复制
→ 上板
→ 看能不能跑
```

出现问题后，这种方式无法判断根因究竟在：

```text
时钟
ADC
OPA
PWM极性
门极驱动
Break
Duty方向
Relay
MPPT
充电状态机
```

## 1.2 两种构建配置

### RELEASE / PRODUCT

默认永远 Fail-closed：

```text
物理 PWM 总门 = OFF
Relay 自动闭合 = 禁止
所有板级验证门 = 0
复位后不允许自动产生功率
```

### BRINGUP / LAB

只供实验室使用，建议具备：

```text
复位后仍默认不发波
串口/SWD手动 ARM
每次复位后重新 ARM
每次故障后取消 ARM
可编译限制最大 Duty
可编译限制单次发波时间
可编译限制最大功率
无自动无限重试
```

初期建议：

```text
Duty ≤ 5%
单次输出 ≤ 100ms
每次故障后必须人工重新 ARM
Relay 不允许自动闭合
```

这些不是最终产品参数，只是 Bring-up 保险丝。

## 1.3 前期抑制项

在相应 Gate 通过前，以下功能必须被“抑制”：

| 未完成 Gate | 必须抑制的功能 |
|---|---|
| G1 未完成 | 所有 ADC/PWM/COMP/Relay 业务 |
| G2 未完成 | 看门狗正式策略、自动启动 |
| G5 未完成 | 任何基于 ADC 工程量的功率控制 |
| G6 未完成 | 门极驱动器输出、实际功率 |
| G7 未完成 | 任意连续 Boost 功率输出 |
| G9 未完成 | 自动闭合 Relay、真实电池接入 |
| G10 未完成 | 自动故障恢复、自动重试 |
| G11 未完成 | MPPT 自动调 Duty |
| G12 未完成 | 真实电池完整充电 |
| G14 未完成 | Demo 实际输出 |
| G15 未完成 | 额定功率声明 |

# 2. G0：硬件、原理图、BOM、PinMap 冻结

## 2.1 目标

确保后续软件调试面对的是**唯一硬件事实**，避免“代码对的是旧图、板子焊的是新 BOM”。

## 2.2 当前必须核实的板级信号

| MCU 引脚 | 信号 | 当前用途 |
|---|---|---|
| PA15 | GLC | ATMR_CH0，当前异步 Boost 低侧 MOS PWM |
| PA14 | GHC | 当前不使用，必须固定安全低 |
| PA13 | RELAY | 继电器，高有效 |
| PA8 | PV_I | ADC CH1 |
| PA9 | PV_U | ADC CH2 |
| PB0 | BAT_U | ADC CH3 |
| PB1 | BST_U | ADC CH4 |
| PB12 | NTC_MOS | ADC CH5 |
| PB5 | NTC_AMB | ADC CH6 |
| PB10 | COMP0_OUT | 开漏，连接 U6 EN，同时关联硬件 Break |
| PB2/PB6 | COMP2 | PV 快速过流比较器输入 |
| PA10/PA11 | UART | 产品串口 |
| PB7/PB8 | DEBUG UART | 调试复用 |

## 2.3 不上电检查

逐项测：

```text
VDD-GND 电阻
PV+-PGND 电阻
BAT+-PGND 电阻
BST_U-PGND 电阻
PA15/GLC 对地阻抗
PA14/GHC 对地阻抗
Relay 线圈阻值
PV 3mΩ shunt 连续性
PV_U 分压阻值
BAT_U 分压阻值
BST_U 分压阻值
两路 NTC 5.1k 上拉
MOS 栅极电阻
Boost 二极管方向
MOS D/S 方向
```

## 2.4 特别检查

必须人工确认：

```text
[ ] PA14/GHC 当前没有作为同步 MOS PWM 使用
[ ] PA15/GLC 到 U6/低侧 MOS 的真实路径正确
[ ] Relay 是常开还是常闭，驱动极性正确
[ ] COMP0 输出故障有效极性
[ ] U6 EN 高/低有效关系
[ ] D2/D3 方向
[ ] L3 实际型号、电感量、饱和电流
[ ] MOS、二极管、Relay、连接器额定值
```

## 2.5 PASS 条件

```text
[ ] 原理图、BOM、实板网络一致
[ ] PinMap 与连续性测试一致
[ ] 无异常低阻短路
[ ] 功率器件方向全部确认
[ ] 异步 Boost 拓扑确认，不再计划移植旧互补同步 PWM
[ ] 形成“G0 硬件基线表”
```

**未通过 G0：禁止烧录 Bring-up 固件。**

# 3. G1：最小工程与上电绝对安全态

## 3.1 本阶段只移植

```text
startup
SystemInit
时钟
最小 GPIO
HardFault / Default_Handler
LED（可选）
```

明确不移植：

```text
ADC
DMA
PWM业务
COMP
Relay业务
MPPT
Charger
Flash业务
完整协议
```

## 3.2 第一条指令链的安全目标

业务初始化之前，必须尽快建立：

```text
GLC = LOW
GHC = LOW
Relay = OFF
LINK = OFF
PWM MOE/输出许可 = OFF
```

即使定时器后续被初始化，物理功率脚也不能出现脉冲。

## 3.3 测试方法 G1-T01：上电/复位毛刺

示波器单次触发：

```text
CH1 VDD
CH2 NRST
CH3 GLC
CH4 Relay Control
```

至少执行：

| 场景 | 次数建议 |
|---|---:|
| 快速上电 | 20 |
| 慢速上电 | 20 |
| 掉电重上电 | 20 |
| NRST 手动复位 | 20 |
| SWD 下载复位 | 20 |
| 看门狗复位（G2 再完整验证） | 预留 |

### 期望

```text
GLC 全过程无窄脉冲
GHC 全过程保持低
Relay 不误吸合
```

## 3.4 G1-T02：HardFault 安全态

开发构建中增加明确的测试入口，主动触发 HardFault。

观察：

```text
进入 HardFault
→ GLC 立即低
→ GHC 低
→ Relay OFF
→ 系统复位或停在安全循环
```

不能依赖“正常主循环下一次执行”才关功率脚。

## 3.5 G1 PASS 条件

```text
[ ] ARMCLANG Rebuild 0 Error / 0 Warning
[ ] MAP 中 APP 未覆盖预留 Flash 区
[ ] 100 次以上混合上电/复位无 GLC 毛刺
[ ] GHC 全程为低
[ ] Relay 从未误吸合
[ ] HardFault 后功率相关 GPIO 进入安全态
```

**失败抑制：** 不允许初始化 PWM AF，不允许给门极驱动器使能。

# 4. G2：弱光稳定启动、时钟、1ms 节拍、UART、看门狗

## 4.1 推荐顺序

```text
弱光/PVD供电资格
→ 系统时钟确认
→ 1ms节拍
→ UART
→ 看门狗
```

### 为什么看门狗不放最前

先有 UART 和可靠时基，才能确认：

```text
是正常 WDG 复位
还是时钟错误/主循环死锁/启动供电不稳定
```

## 4.2 G2-A：弱光 / PVD 供电资格

设计目标：

```text
最小安全 GPIO
→ PVD Ready
→ VDD 连续稳定
→ 满稳定窗口
→ 才初始化完整外设
```

任意一次 VDD 跌落都必须：

```text
稳定计时清零
重新等待完整窗口
```

当前 2.8V / 100ms 只能作为候选，最终用板测冻结。

### 测试输入

建议用可编程电源模拟 MCU 辅助电源，执行：

```text
快速上升
慢斜坡上升
阈值附近三角波
阈值附近周期抖动
超过阈值 50ms 后跌落
超过阈值 99ms 后跌落
超过阈值 101ms 后保持
```

### 判定

```text
未满稳定窗口：
  不启动业务 ADC/PWM/COMP
  不进入无限重启

达到稳定窗口：
  完整启动一次
  不重复初始化
```

## 4.3 G2-B：时钟与 1ms 节拍

使用空闲 GPIO：

```text
1ms Task Entry：Toggle
```

示波器统计：

```text
周期平均值
min/max
峰峰抖动
是否丢 Tick
```

建议初始工程门槛：

```text
平均周期误差符合晶振/内部RC容差
无丢Tick/重复Tick
空载峰峰抖动建议 <10us
```

若采用的时钟源本身精度较差，应按器件规格修改门槛，不能为了“通过”改日志。

## 4.4 G2-C：UART

先做 Debug UART，再接产品协议。

建议启动日志：

```text
BOOT
FW_VERSION
GIT_SHA
RESET_CAUSE
CLOCK_HZ
PVD_STABLE_MS
MIGRATION_GATE=G2
```

测试：

```text
115200 8N1
固定模式连续发送
RX 回环
随机长度帧
缓冲区溢出
10^6 字节连续收发
```

PASS：

```text
[ ] 10^6 字节回环无错误
[ ] RX 满时有统计，不越界写内存
[ ] ISR 不 printf
[ ] 日志发送不会阻塞 1ms Task
```

## 4.5 G2-D：看门狗

先仅监督：

```text
主循环票据
1ms 控制票据
```

人为注入：

```text
主循环 while(1)
停止1ms任务
关闭未来 ADC 票据（G4后）
```

PASS：

```text
[ ] 故意停止喂狗后必定在预期窗口复位
[ ] Reset Cause 能被记录
[ ] 看门狗复位无 GLC/Relay 毛刺
[ ] 正常运行2小时无误复位
```

**认知红线：看门狗是软件卡死兜底，不是 MOS 微秒级保护。**

# 5. G3：ADC 单通道原始码验证

## 5.1 为什么先不做 DMA

这一步只回答三个问题：

```text
ADC 本体配置对不对？
通道映射对不对？
采样时间/建立误差是否合理？
```

不要同时引入 DMA、滤波、物理量换算，否则原始误差被层层处理后更难定位。

## 5.2 测试步骤

### G3-T01：单个 ADC 引脚电压扫描

每次只使能一个通道，外部精密电源直接注入 ADC 合法电压：

```text
0.0V
0.5V
1.0V
1.5V
2.0V
2.5V
3.0V
```

串口打印：

```text
channel
raw
mean_100
min
max
peak_to_peak
vdd_mv
```

理论：

```text
Code_ideal = Vin / Vref * 4095
```

### G3-T02：物理通道映射

逐个只改变一个网络，确认：

```text
PA8  → PV_I
PA9  → PV_U
PB0  → BAT_U
PB1  → BST_U
PB12 → NTC_MOS
PB5  → NTC_AMB
```

禁止仅凭代码枚举认定映射正确。

### G3-T03：高源阻抗建立误差

BAT_U 使用高阻分压，重点验证 ADC 采样保持电容建立时间。

测试法：

```text
A. 前一个扫描通道接近0V
B. BAT_U固定在某电压
C. 记录BAT_U码

再改：
D. 前一个扫描通道接近3.3V
E. BAT_U仍保持相同电压
F. 比较BAT_U码
```

如果结果明显受前一通道影响，应处理：

```text
增加 sampling time
增加 dummy sample
调整扫描顺序
增加缓冲
降低源阻抗
```

## 5.3 建议初始 PASS 门槛

```text
[ ] 六通道映射100%一致
[ ] 原始码单调
[ ] 0~3.0V无异常跳码
[ ] 单通道误差建议≤0.5%FS
[ ] BAT_U切换前序电压后误差仍满足目标
[ ] VREF/VDD实测值已记录
```

这里的 0.5%FS 是 Bring-up 初始目标，不替代最终产品精度规格。

# 6. G4：ADC 定时触发、六通道扫描与 DMA

## 6.1 目标结构

```text
固定 Timer Trigger
→ 6 通道规则扫描
→ DMA 双块/半块
→ 完整块完成
→ sequence++
→ 主循环读取稳定快照
```

## 6.2 DMA ISR 原则

ISR 只允许：

```text
确认哪个块完成
记录 block/sequence
置事件
清中断
```

ISR 禁止：

```text
温度查表
MPPT
Protection复杂状态机
printf
Flash
```

## 6.3 G4-T01：扫描顺序

DMA 数据必须稳定对应：

| Index | 信号 |
|---:|---|
| 0 | PV_I |
| 1 | PV_U |
| 2 | BAT_U |
| 3 | BST_U |
| 4 | NTC_MOS |
| 5 | NTC_AMB |

通过逐通道注入独立电压确认，不允许只靠注释。

## 6.4 G4-T02：块一致性

建议在测试构建中保存：

```text
producer_block
producer_sequence
consumer_sequence
DMA overwrite_count
ADC overrun_count
```

验证：

```text
主循环绝不读取正在被DMA写的块
sequence严格单调
不会出现半新半旧数据
```

## 6.5 G4-T03：Stale/Overrun 故障

人为：

```text
关闭 ADC trigger timer
屏蔽 DMA IRQ
故意延迟主循环消费
```

确认：

```text
sequence停止 → stale被检测
DMA无法及时处理 → overrun被记录
```

此时虽然还没有真实功率，逻辑上也必须进入“数据不可信”。

## 6.6 G4 PASS

```text
[ ] 六通道DMA顺序正确
[ ] producer/consumer无竞态
[ ] sequence严格递增
[ ] stale可检测
[ ] overrun可检测
[ ] 连续2小时无DMA异常
[ ] 看门狗加入ADC健康票据后无误复位
```

# 7. G5：工程量换算与模拟标定

> **G5 是进入功率测试前最重要的 Gate。ADC 工程量没有冻结前，不允许控制算法使用这些值发功率。**

## 7.1 当前理论模型

### PV_U

分压约 26:1：

```text
mV/code ≈ 3300 / 4095 * 26 ≈ 20.95mV/code
```

### BAT_U

分压约 15510/510 ≈ 30.41：

```text
mV/code ≈ 3300 / 4095 * 30.41 ≈ 24.51mV/code
```

### BST_U

当前 125k/5k，仍约 26:1：

```text
理论满量程 ≈ 3.3V * 26 = 85.8V
```

**因此现有硬件不能把 87~93V 区域当成可精确测量范围。软件系数无法恢复已经饱和的信息。**

### PV_I

当前理论模型：

```text
3mΩ Shunt
× 内部OPA 16倍
VCM = AVDD/2
0A名义码 ≈ 2048
正向电流候选 polarity = +1
```

理论约：

```text
1 code ≈ 16.79mA
2A  ≈ +119 code
6A  ≈ +357 code
12A ≈ +715 code
```

最终必须以实板为准。

## 7.2 电压标定点

### PV_U

```text
0 / 5 / 10 / 20 / 30 / 40 / 50V
```

### BAT_U

```text
0 / 10 / 20 / 40 / 48 / 60 / 72 / 84V
```

### BST_U

|---|---|---|

# 17. G15：逐级扩大功率

## 17.1 先冻结“300W”定义

必须明确：

```text
300W = PV输入额定？
```

```text

各档CC目标3A
```

## 17.5 SOA / 降额原则

正式升功率前至少核对：

```text

Relay触点电流/浪涌满足
连接器/铜箔温升满足
```

不使用一个统一“80%规则”替代器件数据手册 SOA；每类器件应按自身规格判断。

# 22. 最重要的五条 Bring-up 红线

1. **没有可信 ADC，就不允许闭环控制。**
2. **没有 COMP→Break→真实 Vgs 证据，就不允许连续功率输出。**
3. **没有关波后新 ADC 和 Relay 压差证据，就不允许真实电池合闸。**
4. **没有固定 Duty 低功率物理验证，就不允许上 MPPT。**
5. **没有逐级 SOA/热测试，就不能因为代码里写了 300W 而称产品已经 300W。**

最终迁移的对象不是“旧工程的文件”，而是已经被实板证明过的能力：

```text
安全启动
→ 可信采样
→ 可控PWM
→ 独立快速关断
→ 低压功率转换
→ 安全Relay
→ 完整保护
→ 稳定闭环
→ MPPT
→ Charger
→ 产品辅助功能
→ Demo
→ 额定功率
```

这也是新工程最容易定位问题、最容易回退、最不容易烧功率器件的迁移方式。
