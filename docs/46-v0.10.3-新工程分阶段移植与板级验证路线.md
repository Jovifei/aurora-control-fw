# 46 · 300W 新工程分阶段移植与板级验证路线

> **用途**：本文件不是“当前工程怎么运行”的说明，而是后续建立一个**新的、从最小系统开始逐级 Bring-up 的 300W 工程**时的执行手册。
>
> **执行原则**：每次只引入一种新的硬件能力或新的能量风险；代码推进遵循 CODE_COMPLETE；进入发能量阶段（G8 起）必须取得上一站硬件保护链的 BOARD_PASS 证据。
>
> **参考基线**：当前 v0.10.3 候选实现、`docs/11-Keil编译与台架验收.md`、`docs/13-硬件引脚与外设绑定.md`、`docs/35-v0.9.0-BST_U量程风险与硬件整改门禁.md`。
>
> **重要边界**：当前 300W 板是**单路异步 Boost**。PA15/GLC 是当前主 PWM；PA14/GHC 在当前硬件中不作为同步 MOS PWM，必须保持安全低电平。不要把旧 120W 的 Q5/Q6 互补 PWM、CHxN、同步整流管、DCM/CCM 切换逻辑机械移植到新板。
>
> **死区的正确说法**（2026-09-01 修订，见 §23.1）：死区是**互补输出专有**的概念——只有上下管换相才需要它。冻结基线是单端输出，因此**不设死区配置项**（而不是"把死区设成 0"）；仍在编译的 legacy 互补实现保留死区 32 tick 是**正当值**，不得改 0。红线的实际执行点是 `drv_io.h` 把 PA14 保持为普通推挽 GPIO 输出低，不靠任何 PWM 宏兜底。
>
> **OTA / IAP**：本路线的 Gate 前置条件里**不移植**；但目标工程已按 Jovi 要求保留为**编译期功能预留开关**（默认关闭），见 §23.4。
>
> **Gate与构建边界**：aurora 生产候选里的 `BOARD_GATE_*` / `BOARD_POWER_OUTPUT_ALLOWED`，以及目标工程（`mppt-charger-300w/Application`）里的 `DRV_DEVICE_GATE_*` / `DRV_DEVICE_POWER_OUTPUT_ALLOWED`，都表示最终验收证据，不是 Bring-up 临时开关。G0~G15 必须使用独立受限 Bring-up 构建（目标工程用 `DRV_DEVICE_MIGRATION_GATE`），仅开放当前 Gate 所需的最小硬件能力；严禁为了进入某个台架阶段提前把尚未完成的最终验收 Gate 置 1。宏改名见 §23.5。
>
> **实施期总原则补充（2026-09-03 修订，见 §23.9）**：
> 1. **已知非线性/查表算法**：在第一次打出该工程量的 Gate 就必须搬产品实现，禁止日志折线脚手架。
> 2. **依赖未开闸模拟前端的通道**：理论式可记账，未开闸前 PASS 不得冻结。
> 3. **双轨状态**：每个 Gate 跟踪 `CODE_COMPLETE` 与 `BOARD_PASS` 两个维度；抬 `MIGRATION_GATE` 只要求本站 `CODE_COMPLETE` + Keil 0E0W，不要求上一站 `BOARD_PASS`；进入会发能量的站（G8 起）必须上一站 `BOARD_PASS`（G7 COMP/Break 实板）。

## 0. 如何使用这份文档

这份路线把迁移分成 16 个 Gate：

```text
G0  硬件/原理图/BOM/PinMap 冻结
 ↓
G1  最小工程 + 上电绝对安全态
 ↓
G2  弱光供电资格 + 时钟 + 1ms节拍 + UART + 看门狗
 ↓
G3  ADC 单通道原始码验证
 ↓
G4  ADC 定时触发 + 六通道扫描 + DMA
 ↓
G5  电压/NTC 工程量换算与标定（PV_I 延期至 G7）
 ↓
G6  单路 PWM 无功率验证
 ↓
G7  门极驱动 + COMP + Break 硬件保护链验证
 ↓
G8  低压限流固定 Duty Boost
 ↓
G9  BST_U 预升压 + Relay 安全闭合
 ↓
G10 完整保护矩阵与故障恢复
 ↓
G11 基础闭环 + 限功率 + MPPT
 ↓
G12 TC/CC/CV/Float/Recharge 充电状态机
 ↓
G13 Flash + 协议 + LED + 长时间运行
 ↓
G14 Demo 无电池带载模式
 ↓
G15 5W → 30W → 100W → 额定功率逐级放大
```

### 0.1 Gate 的双轨推进规则（解开假死）

为避免因实板排队导致固件流水线全面停工（假死），每个 Gate 明确拆分 **代码完成** 与 **板级验收** 两列状态，**严禁将 G0–G4 打包闭环**，仍保持 16 个独立 Gate：

| 状态 | 判定依据 | 允许做什么 |
|---|---|---|
| `CODE_COMPLETE` | 本站算法/驱动严格按清单落地，Keil Rebuild 0 Error / 0 Warning，符号与调用边界自洽 | **允许抬高 `MIGRATION_GATE`**，开下一站分支继续写代码 |
| `BOARD_PASS` | 对应台架项全部实测通过，具备可复现波形、CSV、数值与签字记录，RESULT.md 确认 | **允许打 `bringup-gxx-*` Git Tag**；置对应 `DRV_DEVICE_GATE_*` 验收位 |
| `IN_PROGRESS` | 代码未全落地，或实板未取得有效台架证据 | 不得把本站写成 PASS；未通过 G7 BOARD_PASS 严禁进入 G8 发能量 |

**关键约束规则**：
1. **代码向前推进**：只要本站达到 `CODE_COMPLETE`，即可抬 `DRV_DEVICE_MIGRATION_GATE` 进入下一 Gate 编码，无需等待上一站台架实板完成；
2. **能量硬闭锁**：**进入会发出真实能量的站（G8 起），必须上一站（G7 门极驱动与 COMP/Break 硬件保护链）达到 `BOARD_PASS`**，严禁在无保护证据下上电发波；
3. 证据目录、示波器截图、CSV 仍是必须留档的证据，但作为 `BOARD_PASS` 的验收归档材料，不再阻塞后续纯软件模块的 `CODE_COMPLETE`。

### 0.2 每个 Gate 都必须留下的证据

建议每个 Gate 建立一个目录：

```text
docs/bringup/Gxx-名称/
├─ README.md               本阶段记录
├─ scope.png/svg           接线/测点图，可选
├─ scope-001.png           示波器截图
├─ scope-002.png
├─ meter-data.csv          标定数据，可选
└─ RESULT.md               最终判定
```

至少记录：

| 字段 | 必须填写 |
|---|---|
| PCB 版本 | 例如 C300_MPPT Boost V0.1 |
| BOM 版本 | 关键器件是否替换 |
| 固件 Commit | 精确 SHA |
| Keil/ARMCLANG 版本 | 可复现构建 |
| 仪器型号 | 电源、DMM、示波器、探头、负载 |
| 测试日期 | 年月日 |
| 环境温度 | 模拟标定和热测试尤其重要 |
| 供电设置 | 电压、限流 |
| 负载设置 | 电压/电流/电阻/功率 |
| 测试步骤 | 必须可复现 |
| 理论值 | 公式或预期 |
| 实测值 | 原始证据 |
| 判定 | CODE_COMPLETE / BOARD_PASS / BLOCKED |
| 遗留问题 | 影响安全闭锁或进入下一 Gate 前必须明确（实板未测不阻碍纯代码前推） |

> **双轨判定分流说明**：
> - 固件阶段仅完成驱动移植与编译 0E0W 时，RESULT.md 判定填写 `CODE_COMPLETE`，记录代码 SHA 与构建规模，允许抬高 `MIGRATION_GATE` 继续写下一阶段代码；
> - 上板实测取得波形、CSV 与数值证据后，判定更新为 `BOARD_PASS`；
> - 遗留问题明确区分为“代码阻塞项”（阻碍抬 GATE）与“台架待测项”（只在 BOARD_PASS 门禁起效，不阻碍纯软件继续推进）。

# 1. 总体安全策略

## 1.1 每次只增加一种风险

整个 Bring-up 顺序遵循：

```text
先证明 MCU 能安全活着
→ 再证明“看得准”
→ 再证明“能发对 PWM”
→ 再证明“硬件能自行关断”
→ 最后才允许功率级真正传能
```

严禁下面这种一次性移植：

```text
ADC + PWM + COMP + MPPT + Charger + Relay + Flash
全部复制
→ 上板
→ 看能不能跑
```

出现问题后，这种方式无法判断根因究竟在：

```text
时钟
ADC
OPA
PWM极性
门极驱动
Break
Duty方向
Relay
MPPT
充电状态机
```

## 1.2 两种构建配置

### RELEASE / PRODUCT

默认永远 Fail-closed：

```text
物理 PWM 总门 = OFF
Relay 自动闭合 = 禁止
所有板级验证门 = 0
复位后不允许自动产生功率
```

### BRINGUP / LAB

只供实验室使用，建议具备：

```text
复位后仍默认不发波
串口/SWD手动 ARM
每次复位后重新 ARM
每次故障后取消 ARM
可编译限制最大 Duty
可编译限制单次发波时间
可编译限制最大功率
无自动无限重试
```

初期建议：

```text
Duty ≤ 5%
单次输出 ≤ 100ms
每次故障后必须人工重新 ARM
Relay 不允许自动闭合
```

这些不是最终产品参数，只是 Bring-up 保险丝。

## 1.3 前期抑制项

在相应 Gate 通过前，以下功能必须被“抑制”：

| 未完成 Gate | 必须抑制的功能 |
|---|---|
| G1 未完成 | 所有 ADC/PWM/COMP/Relay 业务 |
| G2 未完成 | 看门狗正式策略、自动启动 |
| G5 电压/NTC 未 BOARD_PASS | 不得用这些量做保护阈值以外的功率决策（G10 以前不应有功率决策） |
| G6 未完成 | 门极驱动器输出、实际功率 |
| G7 未完成 | 任意连续 Boost 功率输出 |
| G7 PV_I 未 §9.6 验收 | 不得用电流读数做闭环限流、均流或 MPPT 控制 |
| G9 未完成 | 自动闭合 Relay、真实电池接入 |
| G10 未完成 | 自动故障恢复、自动重试 |
| G11 未完成 | MPPT 自动调 Duty |
| G12 未完成 | 真实电池完整充电 |
| G14 未完成 | Demo 实际输出 |
| G15 未完成 | 额定功率声明 |

# 2. G0：硬件、原理图、BOM、PinMap 冻结

## 2.1 目标

确保后续软件调试面对的是**唯一硬件事实**，避免“代码对的是旧图、板子焊的是新 BOM”。

## 2.2 当前必须核实的板级信号

| MCU 引脚 | 信号 | 当前用途 |
|---|---|---|
| PA15 | GLC | ATMR_CH0，当前异步 Boost 低侧 MOS PWM |
| PA14 | GHC | 当前不使用，必须固定安全低 |
| PA13 | RELAY | 继电器，高有效 |
| PA8 | PV_I | ADC CH1（铜皮待冻结：见下注，禁止提前假设 PA8 即为 OPA 放大输出） |
| PA9 | PV_U | ADC CH2 |
| PB0 | BAT_U | ADC CH3 |
| PB1 | BST_U | ADC CH4（125k/5k 分压，满量程 85.8V） |
| PB12 | NTC_MOS | ADC CH5 |
| PB5 | NTC_AMB | ADC CH6 |
| PB10 | COMP0_OUT | 开漏，连接 U6 EN，同时关联硬件 Break |
| PB2/PB6 | COMP2 | PV 快速过流比较器输入（PB2=INN，PB6=INP） |
| PA10/PA11 | UART | 产品串口 |
| PB7/PB8 | DEBUG UART | 调试复用 |

> **注（信号定义源）**：引脚网络以 `docs/13-硬件引脚与外设绑定.md` 与原理图为唯一基准（G00 README 若有「PA0/1/2 为 PV_I」属于待更正笔误）。doc13 明确定义：OPA0_O=**PA0**（MOS 分流取样），OPA1_O=**PA5**（PV 电流取样），PA2 为 OPA0_P。禁止写「OPA0 输出为 PA2」。

## 2.3 不上电检查

逐项测：

```text
VDD-GND 电阻
PV+-PGND 电阻
BAT+-PGND 电阻
BST_U-PGND 电阻
PA15/GLC 对地阻抗
PA14/GHC 对地阻抗
Relay 线圈阻值
PV 3mΩ shunt 连续性
PV_U 分压阻值
BAT_U 分压阻值
BST_U 分压阻值
两路 NTC 5.1k 上拉
MOS 栅极电阻
Boost 二极管方向
MOS D/S 方向
```

## 2.4 特别检查与待冻结项

必须人工确认并书面记录：

```text
[ ] PA14/GHC 当前没有作为同步 MOS PWM 使用
[ ] PA15/GLC 到 U6/低侧 MOS 的真实路径正确
[ ] Relay 是常开还是常闭，驱动极性正确
[ ] COMP0 输出故障有效极性
[ ] U6 EN 高/低有效关系
[ ] D2/D3 方向
[ ] L3 实际型号、电感量、饱和电流
[ ] MOS、二极管、Relay、连接器额定值
[ ] G0-T01（OPA→ADC 铜皮冻结）：对照原理图净空表，书面回答：
    1. OPA1_O(PA5) 是否与 PA8 同网？
    2. OPA0_O(PA0) 是否另作 MOS 电流？
    3. PA8 是否纯粹为 ADC 外部焊盘？
    若图纸无短接：G5 日志 PA8 只标 pad_mV，禁止标 PVI=…mA 而不带 OPA_OFF。
    片内是否存在 OPA_O→ADC 通路以数据手册寄存器为准，不凭空假设。
[ ] G0-T02（BST_U ECO 决策节点）：G0 仅冻结「125k/5k → 满量程 85.8V」这一硬件事实，
    不在 G0 擅自改动电阻；将「ECO 决策签字截止日期」锁定在 G5 BOARD_PASS 之前（决策二选一见 §7.6，改板执行在板厂）。
```

## 2.5 PASS 条件

```text
[ ] 原理图、BOM、实板网络一致
[ ] PinMap 与连续性测试一致（含 OPA-ADC 拓扑书面记录）
[ ] 无异常低阻短路
[ ] 功率器件方向全部确认
[ ] 异步 Boost 拓扑确认，不再计划移植旧互补同步 PWM
[ ] BST_U 85.8V 事实入账，ECO 决策责任指向 §7.6
[ ] 形成“G0 硬件基线表”
```

**未通过 G0：禁止烧录 Bring-up 固件。**

# 3. G1：最小工程与上电绝对安全态

## 3.1 本阶段只移植

```text
startup
SystemInit
时钟
最小 GPIO
HardFault / Default_Handler
LED（可选）
```

明确不移植：

```text
ADC
DMA
PWM业务（注意：目标仓允许保留 legacy drv_pwm.c 直至 G6 §8.0 同一提交重写；G1–G5 期间保持零调用点与 DCE 预期，审查不得把死区 32 tick 当本站缺陷。不把「G1 写成单端干净接口」列入本站代码清单）
COMP
Relay业务
MPPT
Charger
Flash业务
完整协议
```

## 3.2 第一条指令链的安全目标

业务初始化之前，必须尽快建立：

```text
GLC = LOW
GHC = LOW
Relay = OFF
LINK = OFF
PWM MOE/输出许可 = OFF
```

即使定时器后续被初始化，物理功率脚也不能出现脉冲。

## 3.3 测试方法 G1-T01：上电/复位毛刺

示波器单次触发：

```text
CH1 VDD
CH2 NRST
CH3 GLC
CH4 Relay Control
```

至少执行：

| 场景 | 次数建议 |
|---|---:|
| 快速上电 | 20 |
| 慢速上电 | 20 |
| 掉电重上电 | 20 |
| NRST 手动复位 | 20 |
| SWD 下载复位 | 20 |
| 看门狗复位（G2 再完整验证） | 预留 |

### 期望

```text
GLC 全过程无窄脉冲
GHC 全过程保持低
Relay 不误吸合
```

## 3.4 G1-T02：HardFault 安全态

开发构建中增加明确的测试入口，主动触发 HardFault。

观察：

```text
进入 HardFault
→ GLC 立即低
→ GHC 低
→ Relay OFF
→ 系统复位或停在安全循环
```

不能依赖“正常主循环下一次执行”才关功率脚。

## 3.5 G1 PASS 条件（双轨）

### CODE_COMPLETE（允许抬 MIGRATION_GATE 到 2 继续编码）：
```text
[ ] ARMCLANG Rebuild 0 Error / 0 Warning
[ ] MAP 中 APP 未覆盖预留 Flash 区
[ ] 上电第一条指令链 GPIO 安全态初始化（GLC/GHC/Relay）已就位
```

### BOARD_PASS（允许打 bringup-g01 Tag）：
```text
[ ] 100 次以上混合上电/复位示波器抓取无 GLC 毛刺
[ ] GHC 全程为低
[ ] Relay 从未误吸合
[ ] HardFault 后功率相关 GPIO 立即进入安全态
```

**失败抑制：** 不允许初始化 PWM AF，不允许给门极驱动器使能。

# 4. G2：弱光稳定启动、时钟、1ms 节拍、UART、看门狗

## 4.1 推荐顺序

```text
弱光/PVD供电资格
→ 系统时钟确认
→ 1ms节拍
→ UART
→ 看门狗
```

### 为什么看门狗不放最前

先有 UART 和可靠时基，才能确认：

```text
是正常 WDG 复位
还是时钟错误/主循环死锁/启动供电不稳定
```

## 4.2 G2-A：弱光 / PVD 供电资格

设计目标：

```text
最小安全 GPIO
→ PVD Ready
→ VDD 连续稳定
→ 满稳定窗口
→ 才初始化完整外设
```

任意一次 VDD 跌落都必须：

```text
稳定计时清零
重新等待完整窗口
```

当前 2.8V / 100ms 只能作为候选，最终用板测冻结。

### 测试输入

建议用可编程电源模拟 MCU 辅助电源，执行：

```text
快速上升
慢斜坡上升
阈值附近三角波
阈值附近周期抖动
超过阈值 50ms 后跌落
超过阈值 99ms 后跌落
超过阈值 101ms 后保持
```

### 判定

```text
未满稳定窗口：
  不启动业务 ADC/PWM/COMP
  不进入无限重启

达到稳定窗口：
  完整启动一次
  不重复初始化
```

## 4.3 G2-B：时钟与 1ms 节拍

使用空闲 GPIO：

```text
1ms Task Entry：Toggle
```

示波器统计：

```text
周期平均值
min/max
峰峰抖动
是否丢 Tick
```

建议初始工程门槛：

```text
平均周期误差符合晶振/内部RC容差
无丢Tick/重复Tick
空载峰峰抖动建议 <10us
```

若采用的时钟源本身精度较差，应按器件规格修改门槛，不能为了“通过”改日志。

## 4.4 G2-C：UART

先做 Debug UART，再接产品协议。

建议启动日志：

```text
BOOT
FW_VERSION
GIT_SHA
RESET_CAUSE
CLOCK_HZ
```

### Bring-up 调试约定（实验室必需，非放宽超时）

IWDT 硬件特性为一旦写入 `0xCCCC` 启动后软件不可关闭。为防止在断点、单步跟踪或 HardFault 现场抓取时被 1000 ms 超时强制复位咬死：
- **Bring-up 调试构建**：允许在初始化或调试脚本中置位 `SCU->DBG` 寄存器的 `SCU_DBG_IWDTDBG`（DDL 接口：`DDL_SCU_DEBUG_IWDT_PAUSE`），使得 CPU 被调试器 Halt 时 IWDT 计数器自动暂停；
- **产品 / RELEASE 构建**：该位必须保持为 0（严禁带入量产构建），CPU 挂死或 Halt 时看门狗仍强制走满复位；
- **验收测试保护**：上述「故意停喂复位」用例执行时，必须确保调试冻结位处于关闭（0）状态，以验证真实的硬件复位窗口；
- **与 LOCKUP 的关系**：G00 已要求 `LOCKUPRSTEN=0`（内核锁定不触发专有复位），若此时 IWDT 亦未设调试冻结，则 HardFault 自旋 1 s 后仍会直接触发 IWDTRST，抹掉现场。故调试冻结是实验室调试必备配置，而不是可选注释。禁止使用「直接关闭看门狗做 G3/G4」这类破坏系统防御的旁路。

**认知红线：看门狗是软件卡死兜底，不是 MOS 微秒级保护。**

# 6. G4：ADC 定时触发、六通道扫描与 DMA

## 6.1 目标结构


## 6.2 DMA ISR 原则

ISR 只允许：


ISR 禁止：

```text

MPPT
Protection复杂状态机
printf

```

DMA 数据必须稳定对应：

| Index | 信号 |
|---:|---|
| 0 | PV_I |
| 1 | PV_U |
| 2 | BAT_U |
| 3 | BST_U |
| 4 | NTC_MOS |
| 5 | NTC_AMB |

通过逐通道注入独立电压确认，不允许只靠注释。

```text
producer_block
producer_sequence
consumer_sequence
DMA overwrite_count

```

```text

sequence严格单调

```

## 6.5 G4-T03：Stale/Overrun 故障

人为：

```text
关闭 ADC trigger timer
屏蔽 DMA IRQ
故意延迟主循环消费
```

确认：

```text
sequence停止 → stale被检测
DMA无法及时处理 → overrun被记录
```

此时虽然还没有真实功率，逻辑上也必须进入“数据不可信”。

## 6.6 测量链与块统计约定（防止标定与控制口径脱节）

1. **ISR 职责边界不变**：ISR 严格禁止温度查表、去极值排序、浮点或复杂滤波，只做双缓冲推指针与置事件（保持 §6.2 原则）。
2. **块统计归属**：完整 DMA 块交付主循环/应用层后，用于后续工程量换算的 raw 码，必须是与 aurora `measurement_process_block` 同类的 **16 次扫描去极值平均**（16 次扫描剔除 1 个最大值与 1 个最小值后求平均，除以 14）。
3. **禁止末次扫描作为标定源**：当前 Bring-up 最小实现中 `publish_block` 若只取块内第 16 次末次扫描，属于单次瞬态样本，**严禁**直接作为 G5 模拟标定的输入数据源，否则比对的是单次瞬态噪声而非稳态物理量。
4. **实施落地时机**：16 次去极值平均的 `CODE_COMPLETE` 允许暂放在 `drv_board` 或 Bring-up `main` 中，可以落在 G4 末或 G5 初，但**必须在 G5 开展正式台架标定前就位**，确保“标定所用 raw”与“未来控制所用 raw”统计口径严格统一。G4 的 `BOARD_PASS` 仍只考核双缓冲顺序、竞态、stale/overrun 与看门狗票据。

# 9. G7：门极驱动、COMP、Break 硬件保护链

> **原则：比较器和硬件 Break 必须在真正传输明显能量之前证明有效。**

## 9.0 开闸清单（抬 `DRV_DEVICE_MIGRATION_GATE` 之前）

1. 把 `drv_device.h` 的 `#error` 上限从 5/6 抬到至少 **7**。COMP 中断桥是 `#if GATE>=7`；只把 GATE 改成 7 而上限仍是 5 会编译失败，上限到 6 但桥接仍被裁掉会让 COMP IRQ 掉进 startup `[WEAK]` 裸死循环且不断功率。

3. `DRV_COMP_Init` 内部不得再把 COMP NVIC 优先级写成 1；冻结表为 0。
4. 在强制触发 COMP 之前，先测量验证 OPA 输出引脚（对照 G0 铜皮表回答，如 PA5/OPA1_O、PA0/OPA0_O）的基础直流偏置是否处于约 AVDD/2 附近。

## 23.1 死区语义纠正

原表述（§重要边界、§8.1）把"死区"列进"不要移植"清单，实施期一度被理解成"死区必须为 0"，并在 `drv_pwm.h` 里写了 `DRV_PWM_DEADTIME_TICKS (0U)` 加 `#error` 守卫。**这个理解是错的**，Jovi 明确纠正：

```text
互补 PWM 是要有死区的。0 的地方删除。
```

正确的说法：

1. 死区是**互补输出专有**的概念，用来防止上下管直通短路。
2. 冻结基线（单路异步 Boost、PA15/GLC 单端输出）**没有互补通道，因此不设死区配置项**——不是"设成 0"，是这一项不存在。
3. 仍在编译的 legacy 实现走 CH0/CH0N 互补输出，它的 `DRV_PWM_LEGACY_DEADTIME_TICKS (32U)` 是**正当值，不得改 0**。
4. 两组值不是"冲突"，是**适用于两种不同拓扑的两套参数**。
5. 已执行：删除 `DRV_PWM_DEADTIME_TICKS (0U)` 及其 `#error` 守卫（删除前已确认零引用，属零消费者变更）。

**红线执行点转移说明**：删掉 `#error` 意味着少了一道编译期守卫。异步 Boost 红线的**实际**执行点是 `drv_io.h` 的 `DRV_IO_PIN_GHC_UNUSED_*`——PA14/GHC 被配置为普通推挽 GPIO 输出低，物理上不接到 ATMR 复用。G6 验收时按 §8.4 用示波器确认 PA14 全程 LOW，这是唯一可信证据，不依赖任何宏。

## 23.2 M0+ 缺失异常 handler 保留

`g32f031_int.h` 声明了 Cortex-M0+ 根本不存在的 `MemManage_Handler` / `BusFault_Handler` / `UsageFault_Handler`。实施期曾报告为"无害残留、可删"，Jovi 裁定：

```text
这几个函数还是保留吧，函数也保留，免得以后使用。
```

已执行：声明保留，并在 `g32f031_int.c` 中补回三个定义。2026-09-01 复审后模板与 `HardFault_Handler` 同构：函数体**首行** `drv_io_force_power_safe()`，再 `while(1)`。函数头注明"M0+ 无此异常、向量表无此项、永远不会被硬件调用、保留供日后移植到带 MPU 的 M3/M4 复用"。M0+ 上三者仍为死代码（OneElfS 会 GC），移植到 M3/M4 时模板本身已断功率。

安全性已验证：`startup_g32f031.s` 向量表既没有这三项入口也没有 weak 符号，故不存在重复符号或缺失符号风险；三者是外部链接，不会触发 `#177-D unused static function`（该工程 `--diag_error=warning`，任何 warning 即 error）。M0+ 上总线错误、非法指令、未对齐访问一律升级为 HardFault，`HardFault_Handler` 仍是唯一实际生效的故障入口。

## 23.5 驱动层命名与两代配置共存

批次 1 之后 Jovi 要求的代码风格收敛，本文档原先未涉及，登记备查：

- 驱动层文件前缀统一 `drv_`（`bsp_ota.*` 是唯一豁免）；删除 `driver.h` 汇总头，应用层各自直接 include；宏按所属模块命名（`DRV_IO_` / `DRV_SYSTEM_` / …），驱动配置放在对应驱动 `.h`，跨模块开关放 `drv_device.h`，驱动层禁止 include 任何 app 头。

- **待重写实现体的函数名保持大写 `DRV_XXX_Yyy` 形式**（如 `DRV_PWM_Init`），这是刻意留下的视觉标记，提示"实现体还是 legacy"；各自重写通过对应 Gate 后才降为小写 `drv_pwm_*`。新写模块必须直接用小写，不得套用该例外。

## 23.6 COMP0 故障极性未对齐（未修，留 G6/G7）

`drv_comp.h` 的 `DRV_COMP0_FAULT_ACTIVE_LOW = 1U` 要求故障时输出拉低，而 `drv_comp.c` 实际用 `DDL_COMP0_OUTPUTPOL_NONINVERTED`，两者没对齐。这是硬件保护极性问题，按"只报告不擅改行为"的规矩**未修**，留到 G6/G7 连同实板强制触发验收一起处理。已记在 `drv_comp.h` 注释与 `docs/bringup/G01-最小安全工程/RESULT.md` §9.6。

**验收要求**：G7（§9 门极驱动、COMP、Break 硬件保护链）必须用**实际强制触发 COMP0** 的方式确认极性，不接受纯静态推断。极性未确认前不得进入 G8 连续功率输出。

## 23.7 COMP2 负端引脚修正（PB1→PB2）

G00 冻结表与数据手册表格 9 均裁定 **COMP2_INN = PB2**、PB1 = ADC_IN4/BST_U，legacy `drv_comp.c` 却按 PB1 配置（GPIO 掩码 `PIN_1|PIN_6` + 枚举 `INPUT_MINUS_PB1`）。2026-09-01 已修正：掩码改 `PIN_2|PIN_6`、枚举改 `_PB2`、注释同步。

要点：

1. DDL 中 `DDL_COMP1_INPUT_MINUS_PB1` 与 `_PB2` **同值**（均 `COMP_CR_VNSEL_0`），改枚举名不改硬件；**真正生效的修正是 GPIO 模拟模式掩码**——不改掩码 PB2 不进模拟模式，COMP2_INN 到不了焊盘。
2. 运行期风险为零（`DRV_COMP_Init` 当前无调用点），但 G7 若照抄旧实现会与 BST_U 抢脚。
3. 顺带记录：legacy `DRV_COMP_Init` 把 COMP0/COMP1_2_3 NVIC 优先级设为 1，与本路线 G00 冻结表（=0）不一致，G7 重写时按冻结表收敛。
4. G7 验收要求：COMP2 实板功能确认（连同 §23.6 的 COMP0 极性强制触发）。

## 23.8 PB1 / BST_U 排在 G3，G2 不配置 ADC

批次 2 范围是弱光/PVD → 时钟 → 1 ms 节拍 → UART → 看门狗。G2-A 判定条款本身要求未满稳定窗口不启动业务 ADC。因此 **GATE=2 不碰 ADC、不把 PB1 配成模拟** 是验收前提，不是漏移植。

PB1 三层现状（2026-09-02 核对）：

1. PinMap / G00 冻结表：PB1 = BST_U = ADC CH4。已冻结。
2. `drv_adc.h`：`DRV_ADC_INDEX_BUS_U (3U)` / `DRV_ADC_CH_BUS_U (4U)`，`CHANNEL_COUNT=6`。头文件已记账。
3. `drv_adc.c` legacy：掩码 PB0|PB5|PB12、rank 无 CH4、`LEGACY_CHANNEL_COUNT (5U)`、`SequencerLength=5RANKS`。三处自洽，搬的是旧一代 5 通道实现，**从来不算 BST_U**。这与 COMP2「枚举说 PB2、掩码却给 PB1」那种自相矛盾不同。

批次 1 不把 5 改成 6：改缓冲数组、rank 表、采样时间属行为变更，必须随 G3 重写整体完成。当前唯一调用点在 `GATE>=3`，镜像里 `drv_adc.o` 零贡献；`drv_io.c` 不碰 PB1，焊盘保持复位默认输入，外挂 26:1 分压无冲突。

G3 开工必须四件一起做（见 §5.0），禁止给 legacy 5 通道打补丁冒充六通道。命名：原理图与 PinMap 用 **BST_U**；头文件现用 **BUS_U** 是同一根 PB1。G3 重写对外统一 BST_U，`BUS_U` 只允许一次性废弃别名。

量程：26:1 分压、3.3 V 参考下理论满量程 ≈85.8 V。该结论是 **G3 PASS 前置**（映射与不可超参考注入必须先写进 RESULT）。是否换分压的硬件整改由 §7.6 二选一闭环，不要塞进 G3。

## 23.9 G5 换算算法与计量门拆分（2026-09-03 裁定）

1. **NTC 算法资产强制归位（反向脚手架禁令）**：
   - 裁定 G5「工程量换算」必须以 120W 的 166 点阻值表（`TabNtc_100K` / `k_ntc_100k_ohm`）加二分插值为唯一基准，直接落入 `drv_board.c`；
   - 严禁任何恒定 $\beta$ 折线或临时十点拟合脚手架进入仓库；
   - 开路（$\ge 4093$）与短路（$\le 64$）物理哨兵直接由底层换算出口拦截并返回哨兵值；
   - 明确 166 点表为固化算法资产，随固件发布，**不属于**单板拟合参数，严禁写入独立 board config；
   - 方向滤波（10 次同向确认）与 1s SENSOR 锁存仍属后续应用层 `measurement.c` / `protection.c` 职责，本站不移植。

2. **PV_I 计量与 OPA 硬件解耦**：
   - G5 阶段内部 OPA×16 尚未开闸（G7 才 Init），3 mΩ 分流器在 1 A 下仅产生 3 mV 压降，ADC PA8 无有效放大信号；
   - 裁定：原 §7.3 / §7.4 / §7.7 中的 PV_I 0A 零点、极性与低电流增益冻结**全部移出 G5 PASS**，统一移交至 §9.6（G7 运放开闸与 OPA 偏置验证后执行）；
   - G5 仅做 PV_I 理论模型记账，日志 PA8 标明 `(OPA_OFF)` 或引脚 mV，严禁冒充已标定电流。

3. **G4 块统计与 G5 标定源对齐**：
   - 确立 G5 标定所使用的 ADC raw 码必须与日后控制算法使用同一套统计口径（16 次扫描去极值平均）；
   - 严禁直接使用 G4 末次单次扫描样本作为 G5 标定依据，防止控制算法接入后产生 K 值二次漂移。

4. **BST_U 85.8V 量程决策闭环**：
   - 终结在 G3/G5/G9/G12 之间的推诿，G5 BOARD_PASS 必须在 §7.6 二选一（A. 硬件 ECO 改分压；B. 永久限定母线 $\le 82\text{ V}$ 并删除 87~93V 用例），禁止第三种选择。

5. **双轨推进机制**：
   - 澄清 16 个 Gate 保持独立，不打包合并；
   - 确立 `CODE_COMPLETE`（代码落地+编译 0E0W，可抬 MIGRATION_GATE 写下一站代码）与 `BOARD_PASS`（台架证据齐全，可打 Tag 置位验收宏）双轨推进规则；
   - 设立绝对安全底线：进入 G8 发能量前，必须取得 G7（门极驱动与 COMP/Break 硬件保护链）的 `BOARD_PASS`。
