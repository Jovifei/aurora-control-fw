# 18 · v0.7.2 目录规范与交接说明

## 1. 本版本调整

v0.7.2 在 v0.7.1 的基础上进一步统一应用层与驱动层的源码布局：

```text
app/
├─ inc/        应用层公开/内部头文件
└─ src/        应用层实现文件

driver/
├─ inc/        每个驱动模块对应的头、公共契约和板级配置
└─ src/        目标 MCU 及板级驱动实现
```

生产代码不再保留`service/`或`board/`产品层；中断桥接、应用入口和运行时编排归入`app/src`，板级配置与板级初始化归入`driver/inc`和`driver/src`。

## 2. 分层职责

- `app/inc`、`app/src`：充电、采样计算、MPPT、保护、功率级、UI、协议、存储、应用入口和运行时编排。
- `app/src/interrupts.c`：ISR/回调与应用运行时之间的轻量桥接；复杂业务全部在主循环执行。
- `driver/inc`：每个驱动模块的对应头文件、公共驱动契约、PinMap和板级安全配置。
- `driver/src`：G32F031 对应外设和板级驱动实现，允许使用芯片 DDL/CMSIS。
- `vendor`：芯片厂商库，不承载产品业务。
- `project`：Keil工程、scatter和用户工程配置。

## 3. 关键约束

1. APP可通过Driver契约调用驱动，但不得直接包含芯片库、CMSIS或DDL头文件。
2. Driver 不得反向依赖 APP 业务模块。
3. ADC 保持“定时器触发 → 多通道扫描 → DMA → ISR只发布完整块 → 主循环换算”。
4. 正常 PWM 只有 `app/src/main.c` 应用运行时一个最终提交出口。
5. Duty 写入 CCR preload，等待自然 UEV 后生效；运行期禁止软件 UG。
6. 故障 ISR 只允许关波、锁存与投递事件，禁止重新发波。
7. `BOARD_POWER_OUTPUT_ALLOWED` 在 Keil、比较器、模拟标定和低压台架完成前保持 0。

## 4. Codex 接手时首先确认

```text
app/src/app.c                不应存在（已与main.c合并）
driver/src/drv_pwm.c         应存在

app/inc/main.h               应存在
app/src/main.c               应存在
app/src/interrupts.c         应存在
driver/inc/driver.h          应存在
driver/inc/drv_pwm.h         应存在
driver/src/drv_board.c       应存在
```

