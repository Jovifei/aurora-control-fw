# 18 · v0.7.2 目录规范与交接说明

## 1. 本版本调整

v0.7.2 在 v0.7.1 的基础上进一步统一应用层与驱动层的源码布局：

```text
app/
├─ inc/        应用层公开/内部头文件
└─ src/        应用层实现文件

driver/
├─ inc/        芯片驱动统一接口头文件
└─ src/        目标 MCU 驱动实现
```

`service/` 与 `board/` 当前文件数量较少，继续保持扁平，避免为了形式增加无意义层级。

## 2. 分层职责

- `app/inc`、`app/src`：充电、采样计算、MPPT、保护、功率级、UI、协议、存储等纯业务。
- `service`：ISR/回调与 APP、Driver 之间的桥接；负责事件邮箱、DMA完成块消费、PWM最终提交、看门狗健康监督等。
- `driver/inc`：MCU驱动统一接口，只描述 ADC/PWM/COMP/UART/Flash/WDT/GPIO 等驱动契约。
- `driver/src`：G32F031 对应驱动实现，允许使用芯片 DDL/CMSIS。
- `board`：引脚、极性、ADC标定、功率档和板级安全门禁。
- `vendor`：芯片厂商库，不承载产品业务。
- `project/keil`：目标入口、启动工程和链接配置。

## 3. 关键约束

1. APP 不得直接包含芯片库、Driver、Board 或 Service 头文件。
2. Driver 不得反向依赖 APP 业务模块。
3. ADC 保持“定时器触发 → 多通道扫描 → DMA → ISR只发布完整块 → 主循环换算”。
4. 正常 PWM 只有 Service 一个最终提交出口。
5. Duty 写入 CCR preload，等待自然 UEV 后生效；运行期禁止软件 UG。
6. 故障 ISR 只允许关波、锁存与投递事件，禁止重新发波。
7. `BOARD_POWER_OUTPUT_ALLOWED` 在 Keil、比较器、模拟标定和低压台架完成前保持 0。

## 4. Codex 接手时首先确认

```text
app/app.c                    不应存在
driver/drv_pwm.c             不应存在

app/inc/app.h                应存在
app/src/app.c                应存在
driver/inc/driver.h          应存在
driver/src/drv_pwm.c         应存在
```

修改后至少运行：

```bash
python tools/check_architecture.py
python tools/check_code_style.py
python tools/run_checks.py
python tools/check_target_syntax.py
```
