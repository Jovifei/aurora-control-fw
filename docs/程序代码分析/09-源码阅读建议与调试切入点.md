# 09｜源码阅读建议与调试切入点

## 1. 最推荐的阅读路线

如果你是第一次系统读这份 300W 工程，建议按下面顺序：

### 第一遍：建立结构感

1. `app/inc/app_types.h`
2. `app/inc/main.h`
3. `docs/02-软件分层与依赖规则.md`
4. 本目录 `01-系统总览与代码地图.md`

目标：知道有哪些状态、有哪些组合根、模块之间怎么分工。

### 第二遍：抓主循环

1. `app/src/main.c`
2. `app/src/interrupts.c`
3. 本目录 `02-main与interrupts运行入口分析.md`

目标：知道事件是怎么流动的。

### 第三遍：读控制数据源

1. `app/src/measurement.c`
2. `driver/src/drv_adc.c`
3. `driver/src/drv_board.c`
4. 本目录 `03-measurement测量模块代码分析.md`

目标：知道所有控制量从哪里来，以及何时可信。

### 第四遍：读三大控制模块

1. `app/src/charger.c`
2. `app/src/mppt.c`
3. `app/src/power_stage.c`
4. `app/src/protection.c`

目标：知道“想怎么充”“想怎么取能”“能不能执行”“何时必须停机”。

### 第五遍：读外围模块

1. `protocol.c`
2. `storage.c`
3. `ui.c`
4. 各 driver 文件

目标：知道调参、掉电保存、通信和可视化状态。

### 运行主线断点

- `aurora_runtime_init()`

### 保护链断点

### measurement

- `sample.battery_voltage_mv`
- `sample.bus_voltage_mv`

## 4. 最常见的“读不懂”根因

### 误区 1：把 charger 当成最终执行器

不是。最终动作一定要看 `power_stage`。

### 误区 2：把 MPPT 输出当成最终 Duty

不是。MPPT 输出的是理论功率请求。

### 误区 3：忽略 measurement 的 valid_mask

如果一个量还不 valid，后面的判断都可能不成立。

### 误区 4：只看主循环，不看 ISR

这样会不知道事件是从哪里来的。

### 误区 5：只看 app，不看 driver

这样会不知道硬件极性、扫描顺序、门禁和标定来源。

## 5. 建议你最终形成的心智模型

当你把源码读熟后，脑中应该能用一句话描述系统：

> **ADC DMA 周期性发布测量快照；charger 生成电池侧目标，mppt 生成 PV 侧理论请求，protection 判断是否安全，power_stage 把这些结果裁决成 PWM 和继电器命令，runtime 再通过 driver 落地到硬件。**

如果这句话你已经完全理解，那么后面再去逐行读代码，速度会快很多。
