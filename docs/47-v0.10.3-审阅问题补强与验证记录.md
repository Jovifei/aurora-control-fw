# 47 · v0.10.3 审阅问题补强与验证记录

本文件记录 v0.10.3 安全握手与快速故障链的软件收尾。后续新增的 Flash/旧EEPROM风险闭环见 [48-v0.10.3-Flash边界与停机保存闭环](48-v0.10.3-Flash边界与停机保存闭环.md)；当前主线真实进度与待测项见 [49-v0.10.3-当前主线状态与下一步待测试总表](49-v0.10.3-当前主线状态与下一步待测试总表.md)。

本轮软件边界不移植 OTA/IAP 运行功能，不修改 3A CC、12A PV 限流、BST_U 分压 BOM，也不打开任何生产功率门禁。

## 1. Relay 与 Demo

- `RELAY_HOLD_OFF` 的 ADC 基准由 Runtime 在物理 `drv_pwm_disarm()` 后记录，不再由 PowerStage 在关波前记录。
- 至少跨过两个新的 DMA 发布代次并满足 20ms 放能，才允许重新复核。
- Relay执行反馈收敛为单线程Runtime的 `relay_applied`；Battery/Demo每次闭合前都强制经过HOLD_OFF物理断开，不维护额外generation事务机。
- Battery 仍要求压差 <=1.5V；Demo 使用独立闭合判据，并受30W硬功率上限约束。
- 关波后压差丢失超过500ms按有限预充失败处理，不再 PRECHARGE/HOLD_OFF 无限循环。

## 2. 预充与快速故障

- COMP ISR不再依据故障发生后已经被硬件Break清掉的MOE判断故障前状态；故障分类使用软件PWM ARM状态。
- `drv_pwm_arm()` 前先把软件状态置入ACTIVE，覆盖“硬件刚放行、故障立即发生”的竞态窗口。
- WAIT_ZERO保持为启动瞬态窗口，不把0 Duty等待UEV期间的比较器抖动直接锁存为运行期FAST OCP。
- PRECHARGE分类恢复定稿规则：只有PV跌出13V启动窗口才归类 `PV_WEAK`；只要PV仍在启动窗口，30s无法建立BUS均压一律 `BUS_PRECHARGE_TIMEOUT`。
- `clear_startup_break_if_safe()` 要求 `pending_fault_mask==0`，避免ISR已投递但Protection尚未锁存时提前清Break证据。

## 3. 能量与旧协议

- Protection 在能量资格判断前更新；PV能量只在 PRECHARGE / Battery RUN / Demo Probe/Run 且物理PWM输出、样本新鲜有效时累计。
- 能量时间使用 ADC `sequence/timestamp_ms` 差值；首个样本只建立时间基准，不用单点功率外推长时间。
- 旧30字节帧**布局与v0.10.2字段语义均保持不变**：daily/lifetime继续发送PV实测 `daily_energy_wh/lifetime_energy_wh`。
- `charge_est_*`继续保存在Flash v3内部独立账本；无BAT_I硬件时它只能标记为ESTIMATED，后续如需对外提供应使用新资源或版本化协议，不能静默替换旧字段语义。

> 早期收尾记录曾出现“旧30字节恢复120W电池侧估算语义”的文字，该说法与最终源码和定稿测试不一致，现已统一删除。最终口径以上述PV实测语义为准。

## 4. 序号回绕与Host门禁

- `relay_holdoff_sequence`不再使用`0`作为“未捕获”哨兵；使用独立`relay_holdoff_sequence_valid`。
- 即使32位ADC发布序号自然回绕到0，HOLD_OFF仍按无符号差值等待两个新DMA发布块，不会永久卡死。
- `AURORA_HOST_TEST_POWER_GATES_OPEN`只能在同时定义`AURORA_HOST_TEST`的Host目标使用；目标固件误配该宏会直接`#error`。
- `BOARD_GATE_*`与`BOARD_POWER_OUTPUT_ALLOWED`是最终验收证据门，不是Bring-up临时开关；低压/分阶段板测使用46号路线中的独立受限Bring-up构建。
