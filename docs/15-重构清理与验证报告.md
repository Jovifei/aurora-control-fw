# 15 · 重构清理与验证报告

## 1. 对远端当前提交的审查结论

远端`main`最初提交是研究归档式打包，不是可直接维护的量产嵌入式工程。主要问题包括：

- 根目录和`firmware/`内重复放置tests/tools/docs；
- `firmware/docs`主要是生成JSON，不是真正文档；
- 保留完整旧MCU源码与协议聚焦副本；
- APP目录混入历史parity、协议导入和厂商`arm_*`文件；
- 应用功能过度碎片化，measurement、pipeline、estimator、modulator等边界重复；
- 完整SDK和大量示例进入交付包；
- 最新提交没有远端CI状态可作为构建证据。

## 2. 本清理版删除或重组的内容

```text
删除 firmware/ 外壳
删除 tasks/
删除 legacy_reference/ht32_original
删除 legacy_parity 与 legacy_protocol_import
删除所有生成JSON
删除应用目录中的arm_*和旧闭源MPPT依赖
删除重复tests/tools/docs
删除完整SDK示例，只保留实际目标构建所需Vendor文件
```

APP合并为9个明确功能模块，并按 `app/inc`/`app/src` 分离接口与实现；Driver扁平化为8个目标驱动；文档扩展到00～19。

## 3. 本轮额外修复

- 最终PinMap改为PA10/PA11 UART、PB9 RUN、PB10 COMP0_OUT、PB11 FAULT；
- 删除已不存在的BAT_S1/BAT_S2输入；
- COMP0_O按开漏、故障低有效实现，ATMR Break对应低有效；
- ADC外部触发启动补上`DDL_ADC_StartConversion()`；
- 六通道采样时间从32/64周期改为8/16周期，避免50 kHz触发下序列超期；
- ADC触发改为CH3中点下降沿；
- DMA处理中同半块绕回会锁存overrun；
- 预充时BST_U低于PV_U不再返回0 Duty导致永远无法建立母线；
- MOS温度和环境温度使用独立去抖计数器；
- 看门狗必须看到主循环和控制心跳，功率状态还必须看到ADC进展；
- UART ISR和主循环均增加处理预算；
- 运行期Duty只写preload，首次0占空比由一次性UPDATE中断确认。

- Windows Keil ARM Compiler 6真实链接、`.map`和Flash/RAM占用；
- 目标板ADC OVR与采样相位；
- OPA零点、比例和温漂；
- COMP0低有效EN与ATMR Break的实物链；
- 继电器两端压差、触点稳定和30分钟断开；
- 首脉冲、GLC/Vgs、MOS/二极管/电感温升；
- 从限流低压到额定功率的完整台架验收。

因此本版本是“清洁、可审查、Host验证的软件基线”，不是“可直接上额定功率”的发布固件。
