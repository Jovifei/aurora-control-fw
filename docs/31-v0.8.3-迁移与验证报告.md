# 31 · v0.8.3 迁移与验证报告

## 1. 本版本目标

v0.8.3把首方生产代码从：

```text
APP + Service + Board + Driver
```

收敛为：

```text
APP → Driver → Vendor
```

此版本主要是结构重构，不重新定义充电参数、MPPT算法、PVD策略或功率安全边界。

## 3. 行为保持项

### 3.1 PWM

保留：

- 单路PA15/GLC异步Boost；
- CCR preload；
- 运行期禁止软件UG；
- 首次PWM先提交0 Duty并等待自然UEV；
- safety epoch阻止故障ISR之后旧路径重新发波；
- Automatic Output关闭；
- Break锁存必须显式恢复。

### 3.2 Relay

保留硬顺序：

```text
Relay OFF
→ Boost先充BST_U
→ |BST_U-BAT_U|<=1.5V持续1s
→ PWM OFF
→ main.c再次实时复核
→ Relay ON
→ 100ms复核<=2.5V
→ BAT_U 10s稳定
→ RUN
```

### 3.3 弱光MCU供电

保留v0.8.1：

```text
VPVD候选2.8V
PVD Ready
VDD连续稳定100ms
→ 才完整初始化
```

PVD IRQ和PVD系统复位继续禁止。

### 3.4 充电/保护

保留v0.8.0 V2.7行为，包括：

- 12组电池档案；
- 多级BAT OV/PV OCP；
- 95°C开始MOS降额；
- 无BAT_I情况下使用估算电流；
- 真正无发电30min才断Relay/Link；
- 弱光/温度/输入限幅不能误触尾流判满。

## 5. Host测试兼容策略

为了避免一次结构重构顺带重写数百行业务测试，`tests/`保留三个仅测试使用的兼容头：

```text
tests/app.h
tests/service.h
tests/board.h
```

它们把旧测试符号映射到新的 `main.h` / `aurora_runtime_*` / `drv_board_*`。

这些文件：

- 不进入Keil工程；
- 不属于生产架构；
- 后续可逐步把旧测试直接迁移到新命名后删除。

同时新增 `tests/test_two_layer_architecture.py`，确保生产目录不会重新长回Service/Board层。

## 8. 仍未完成的硬件验证

v0.8.3不会把目录重构当成硬件验收。以下继续保持未完成：

- Keil ARM Compiler 6真实完整链接和MAP；
- PVD 2.8V/3.2V弱光启动实测比较；
- ADC比例、OPA方向、PV_I运行时零点标定；
- COMP0/COMP2极性和Break到Vgs关断时间；
- BST_U/BAT_U/Relay/GLC四通道预充波形；
- 300W基础PV限流、过功率和95~104°C降额曲线；
- 低压限流到额定功率温升/SOA验证。

因此：

```c
BOARD_POWER_OUTPUT_ALLOWED == 0
```

必须继续保持。

## 9. 版本审核重点

审核v0.8.3时不要只看目录是否变漂亮，重点检查：

1. `app/src/main.c`虽然合并三个文件，但内部职责仍按static函数拆分，不形成单一超长God Function；
2. 业务模块没有开始直接调用Driver；
3. `interrupts.c`彻底没有DDL/寄存器访问；
4. `driver/src/*.c`没有APP依赖；
5. Relay实时二次复核没有因删除Service而丢失；
6. PWM安全epoch和0 CCR自然UEV握手仍存在；
7. PVD弱光等待仍发生在IWDT/PWM/ADC初始化之前；
8. 功率总门仍为0。

只有这些都成立，才算真正完成“两层产品架构”而不是简单移动文件。
