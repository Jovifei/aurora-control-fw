# v0.10.2 Keil ARMCLANG 修复与发布边界

## 1. 已处理的编译问题

### Scatter 默认 RW 区

`project/AuroraControl.sct` 明确包含：

```text
ER_IROM1: RESET / InRoot / RO / XO
RW_IRAM1: RW / ZI
```

Flash 代码区限制在 `0x00000000..0x0000FBFF`，最后 1 KiB 保留给双页 Flash Journal。

### `-Wpadded`

Keil 工程仍使用 `-Werror`，但对普通 C 结构体自然对齐警告增加：

```text
-Wno-padded
```

未使用 `packed` 结构体，避免 Cortex-M0+ 非对齐访问风险。

### `-Wswitch-enum` 与 `-Wcovered-switch-default`

电压平台 `lead_cell_count()` 显式列出全部 `aurora_battery_pack_t` 枚举，包括 `AURORA_PACK_COUNT`。ARMCLANG 在 `-Wextra -Werror` 下会把已覆盖全部枚举的 `default` 判为错误，因此 COUNT 与越界强制转换值落到 switch 之后的 `return 0U`，不再保留 `default`，也不允许用 `-Wno-covered-switch-default` 消警告。

### `-Wunreachable-code-break`

供电稳定等待中的编译期常量分支改为 `#if`，不再保留编译器可证明永远不可达的 `break`。

## 2. Keil 工程配置

- 工程：`project/AuroraControl.uvprojx`
- Scatter：`project/AuroraControl.sct`
- IROM：`0x00000000`, 大小 `0x0000FC00`
- IRAM：`0x20000000`, 大小 `0x00002000`
- ARMCLANG 参数包含：`-std=c11 -Wall -Wextra -Werror -Wno-padded`

## 3. 本地必须执行的目标验证

在 Windows Keil 中执行 Rebuild All，并确认：

1. 生成 AXF；
2. RO 末地址小于 `0x0000FC00`；
3. RW/ZI 位于 `0x20000000..0x20001FFF`；
4. `0xFC00` 与 `0xFE00` 两个 Journal 页未被链接器分配；
5. 无 ARMCLANG warning/error；
6. MAP 文件与实际工程配置一致。

## 4. 发布边界

只有获得真实 Keil 编译日志、AXF 和 MAP 后，才允许将：

```c
BOARD_GATE_KEIL_LINKED
```

改为 1。Host GCC/Clang 通过不能替代 Keil 链接证据。
