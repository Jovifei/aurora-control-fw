## 1. 背景

120W 旧工程的虚拟 EEPROM 曾出现过一种高危失效链：EEPROM 变量表长度与实际地址数量不一致、初始化失败返回值未形成写禁止条件、活动写地址保持 BSS 初值 0，随后写接口可能把地址 `0x00000000` 当成合法目标，最终破坏向量表/Boot 区。演示模式无电池缓冲时电源跌落更陡，更容易放大“掉电/重启 + Flash 状态恢复失败”的窗口。

300W 工程**不移植**旧式 `guActiveAddress`/`TransferPage` EEPROM 仿真，而使用最后两页固定地址的双页 Flash Journal。本文把旧问题转化为 300W 必须永久满足的安全合同。

## 2. 300W 固定 Flash 布局

```text
0x00000000 ... 0x0000FBFF   固件代码/常量（Scatter限制到0xFC00之前）
0x0000FC00 ... 0x0000FDFF   Journal Page A，512B
0x0000FE00 ... 0x0000FFFF   Journal Page B，512B
```

`project/AuroraControl.sct`、`driver/inc/board_config.h` 与 `driver/src/drv_flash.c` 三处必须一致。

Driver层永久规则：

```text
只允许最后1KiB参数保留区
只允许单个物理页内编程
地址0拒绝
0长度拒绝
未按4字节对齐拒绝
越界拒绝
A页跨B页拒绝
PWM active时拒绝erase/program
```

因此旧120W的“活动地址异常为0 → 写0x00000000”失效模式即使上层再次出现错误状态，也会在Driver边界被拒绝。

## 3. 不使用欠压/LVD/PVD抢写 Flash

300W 运行期**不在欠压事件中执行 Flash 擦写**。PVD只用于上电供电资格：

```text
复位
→ PVD确认VDD稳定
→ 关闭PVD资格监视
→ 正常运行
```

禁止设计成：

```text
LVD/PVD发现VDD正在下降
→ 立即erase/program
→ 试图抢最后一笔数据
```

突然掉电时允许丢失尚未落盘的RAM增量，但禁止为了“抢最后一笔”在电压已经塌陷时启动擦除/编程。安全目标优先级是：

1. 不破坏程序区；
2. 不同时破坏两份Journal；
3. 最后才是尽量保存最新统计量。

## 4. 只在明确停机状态写入

即使PWM和Relay当前恰好为OFF，也不足以证明可以写Flash。运行层只允许以下功率状态触发保存：

```text
WAIT_PV
NO_SUN
FAULT
OFF
```

并继续同时要求：

```text
PWM物理关闭
Relay物理断开
dirty保持时间满足
write_blocked == false
```

以下状态全部禁止写入：

```text
ZERO_CAL
PRECHARGE
RELAY_HOLD_OFF
RELAY_SETTLE
BAT_STABILITY
RUN
DEMO_OUTPUT_CHECK
DEMO_RELAY_SETTLE
DEMO_PROBE
DEMO_RUN
```

这条规则直接对应“EEPROM在停机时写，不要用欠压写”的产品要求。

## 5. 双页事务规则

每次写入遵循：

```text
保留 current_sequence / active_page（上一份有效证据）
→ 选择 active_page 的另一物理页
→ 用 next_sequence 在RAM编码未提交页
→ 恢复RAM current_sequence
→ 擦目标页
→ 写除Commit Marker外的数据
→ 最后写Commit Marker
→ 逐4字节回读验证
→ 全部成功后才更新RAM sequence和active_page
```

任何一步失败：

```text
sequence不前移
active_page不切换
上一份有效页不擦除
保持dirty
1s后最多重试一次
再次失败后write_blocked=true，本次上电不再擦写
锁存STORAGE故障
```

因此不会出现旧实现里的放大链：

```text
第一次写失败
→ RAM sequence已经提前前移
→ 第二次重试换到另一物理页
→ 把上一份唯一有效页也擦掉
```

## 6. 为什么不再依赖 sequence 奇偶选择页

正常写入时奇偶确实可以形成A/B交替，但异常恢复、历史页、人工烧录或未来格式迁移不能假设“奇数一定在A、偶数一定在B”。

运行上下文明确保存最后有效记录来自：

```text
AURORA_STORAGE_ACTIVE_PAGE_A
或
AURORA_STORAGE_ACTIVE_PAGE_B
```

下一笔永远写另一页。`sequence`只负责判断记录新旧，不负责决定物理地址。

## 7. 编译期布局保护

`storage.h` 编译期验证：

- v3最后一个字段结束位置必须等于 `AURORA_STORAGE_PAYLOAD_SIZE`；
- Header + Payload 必须小于等于512B；
- 总编码长度保持4字节对齐；
- Commit Marker必须位于固定Header内。

这对应旧120W `EEPROM1_EMU_LENGTH` 与实际变量数量不一致的教训：**变量布局变化必须让编译立即失败，而不是运行数月后靠页迁移才暴露。**

## 8. 已完成的软件自动化验证

永久回归已经覆盖：

1. 地址0写入被拒绝；
2. 0长度写入被拒绝；
3. A页尾跨B页写入被拒绝；
4. PRECHARGE即使PWM/Relay均OFF也不写Flash；
5. WAIT_PV停机态允许正常事务；
6. 编程失败后`sequence/active_page`保持上一份有效值；
7. 连续两次失败后停止本次上电继续擦写；
8. 构造“A页 + 偶数sequence”仍写B页，证明不依赖奇偶推断；
9. PVD保持启动资格用途，不形成Flash保存触发链；
10. Host/GCC/Clang/Sanitizer/Cortex-M0+语法门均通过。

当前永久Python合同总数为33项，其中4项为Flash安全合同。

## 10. 与46号路线的关系

Flash代码现在已经是参考主线的软件事实，但**板级Flash验收仍属于G13**。

因此：

```text
现在：Flash software contract = CLOSED
现在：Flash BOARD_PASS = NO
G13完成随机断电/协议/LED/24h运行后：才允许记BOARD_PASS
```

不要因为软件CI全绿就提前把G13写成PASS。
