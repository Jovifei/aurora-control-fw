# 45 · v0.10.3 安全握手与快速故障修复说明

## 1. 版本定位

v0.10.3 只关闭已经有源码证据的软件缺陷，使当前固件具备进入低压限流台架的资格。它不表示300W功率已闭环，也不表示120W所有硬件能力已经等价迁移。

本版本明确不实现：

```text
OTA / IAP / Bootloader
BAT_I实测与电池反向电流快速检测
同步整流Q5
旧Q9/Q11软接通
独立硬件BAT OVP
```

同时不修改：

```text
CC目标3A
PV输入限流12A
BST_U分压BOM
任何BOARD_GATE_*
BOARD_POWER_OUTPUT_ALLOWED
```

## 2. COMP / Break 分类修复

真实硬件可能先由ATMR Break撤销MOE，CPU随后才进入COMP/Break ISR。因此，ISR不能用故障后的 `drv_pwm_output_active()` 单独判断故障前是否已经发波。

v0.10.3 使用软件授权状态：

```text
ARM_OFF       未申请发波
ARM_WAIT_ZERO 零CCR等待自然UEV；属于启动瞬态窗口
ARM_ACTIVE    已进入MOE申请或已经输出；任何Break均按运行故障锁存
```

在调用 `drv_pwm_arm()` 前先发布 `ARM_ACTIVE`。这样即使硬件Break先清MOE，ISR仍能依据故障前的软件授权锁存快速故障。`WAIT_ZERO` 不按运行OCP锁存，保持原有启动瞬态语义。

## 3. Battery Relay闭合顺序

Battery模式执行：

```text
BUS_PRECHARGE
→ |BST_U-BAT_U| ≤ 1.5V 连续1s
→ RELAY_HOLD_OFF：PWM命令关闭、Relay保持断开
→ 等待20ms放能窗口
→ 至少跨两个新的完整DMA发布代次
→ 再次确认BUS有效、未饱和、未过压、压差仍≤1.5V
→ 请求Relay GPIO闭合
→ Runtime实际写出后，PowerStage才开始100ms机械稳定计时
→ 闭合后压差≤2.5V
→ BAT_U稳定10s
→ RUN
```

`relay_applied` 的含义只是“Runtime已经写出Relay GPIO命令”，不是机械触点反馈。触点路径仍通过100ms机械等待、闭合后二次压差和BAT_U稳定窗口间接验证。

预充失败计数在闭合后2.5V复核成功时清零，不在GPIO刚写出时清零。

## 4. Demo Relay与30W边界

Demo不复用Battery的 `BST_U≈BAT_U` 条件。闭合前要求：

```text
Operating Mode = DEMO_LOAD
PWM物理关闭
无软件/快速故障
BAT_U输出端不高于5V外部有源检测阈值
BST_U有效、未饱和且闭合前不高于5V低风险阈值
Demo独立台架门已放行
```

Runtime写出Relay GPIO以后，PowerStage才允许进入100ms机械稳定并继续低功率Probe。

由于当前板没有输出电流传感器，Demo功率增加不可绕过的30W软件硬顶：

```text
协议写入 >30W → INVALID
旧Flash值 >30W → 启动时钳制到30W并安排安全窗口重写
运行时输出 → 再次min到30W
```

Demo仍只能描述为受限恒压和输入功率限制，不能宣称真实恒流输出。

## 5. 预充失败分类

进入BUS_PRECHARGE后，如果PV电压仍在启动窗口，但BST_U在30s内无法建立，则一律归类：

```text
BUS_PRECHARGE_TIMEOUT
```

不再根据预充末端的低Ppv把它改判成 `PV_WEAK`。低Ppv也可能来自MOS未驱动、电感/二极管开路或Boost路径异常；误判为弱光会形成无限重试。

只有PV电压真实跌出13V启动窗口时，才返回 `PV_WEAK`，且不消耗硬件失败次数。

## 6. 能量统计修复与协议边界

PV能量累计新增资格：

```text
PV_POWER有效
sequence非0
样本未超过50ms
没有ADC_STALE / ADC_DMA / ADC_OVERRUN
物理PWM实际输出
Ppv > 0
```

因此ADC停止更新后，最后一帧缓存的正功率不会继续累计。

电池侧估算能量和15h/180min计时继续要求Battery模式、RUN、Relay GPIO已应用、物理PWM、Charger许可和有效PV功率。

本版本保持v0.10.2既有30字节遥测布局与字段语义：旧daily/lifetime energy字段继续发送PV实测账本 `daily_energy_wh/lifetime_energy_wh`。Flash v3仍独立保存 `charge_est_*` 电池侧估算账本，但本版本不静默替换旧协议字段；若后续需要公开该估算量，应通过新资源或明确版本化协议。

## 7. 行为级回归

新增独立 `aurora_v0103_tests`，覆盖：

1. 硬件Break先清MOE、ISR后到仍锁存运行故障；
2. WAIT_ZERO阶段COMP只记录启动诊断；
3. Battery Relay必须经过20ms Hold-off并至少跨两个新的DMA发布代次；
4. Relay未实际应用时不推进100ms稳定阶段；
5. 预充低Ppv超时仍归BUS预充失败；
6. Demo Relay按独立条件闭合，输出端外部电压会拒绝；
7. Demo配置超过30W被拒绝；
8. 陈旧正功率不累计PV能量。

原有Host回归保留，不通过删除测试获得绿色结果。
