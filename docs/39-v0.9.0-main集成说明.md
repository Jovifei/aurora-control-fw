# 39 · v0.9.0 main 集成说明

## 1. 集成决策

V0.9.0 软件收尾完成并通过分支 CI 后，按项目维护者明确指令将代码集成到 `main`。

这里必须区分两个概念：

- **代码集成到 main**：允许，用于让主分支持续承载最新的软件实现与文档；
- **实功率/量产放行**：仍禁止，必须等待模拟标定、COMP/Break、BST_U 量程和低压功率台架等 P0 证据闭环。

因此，本次集成不会把任何硬件门禁改成已验证状态。

## 2. 合并原则

主分支与 V0.9.0 已发生并行开发，不能使用覆盖式更新。本次采用语义合并：

1. V0.9.0 的模拟采样、NTC、PV_I 零点质量、BST_U 饱和 fail-safe、铅酸温补和成熟充电时序作为业务/安全基线；
2. 保留 main 中与安全逻辑不冲突的 clangd、VS Code、格式化和开发工具配置；
3. 冲突文件优先保证 `APP → Driver → Vendor` 两层边界、PWM/Break/Relay 顺序和 V0.9.0 回归合同；
4. 不使用 force push 覆盖 main 历史，而以双父 merge commit 留下可审计合并记录。

## 3. 合并后仍锁定的门禁

以下值继续保持：

```c
BOARD_GATE_COMP_ROUTE_VALIDATED = 0
BOARD_GATE_ANALOG_CALIBRATED    = 0
BOARD_GATE_KEIL_LINKED          = 0
BOARD_GATE_LOW_VOLTAGE_BENCH    = 0
BOARD_POWER_OUTPUT_ALLOWED      = 0
```

这意味着代码进入 `main` 后仍不能据此宣称硬件可安全输出 300W。

## 4. P0 未闭环项

- BST_U 125k/5k 在 3.3V ADC 下约 85.8V 满量程的硬件整改/确认；
- PV_I 正向极性实测；
- PV_I 零点均值、spread、温漂和重复性冻结；
- 内部 OPA ×16 共模/输出摆幅和大电流区线性；
- COMP → Break → MOE → 实际栅极关断全链路；
- Keil AC6/MAP 与低压功率台架。

因此 `main` 代表“已集成的软件候选基线”，不是“已解除功率门的量产版本”。
