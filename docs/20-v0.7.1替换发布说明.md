# 20 · v0.7.1 替换发布说明

## 1. 为什么发布 v0.7.1

远端 `main` 仍保留旧的 APP 扁平目录（`app/*.c`、`app/*.h`），说明 v0.7.0 的“可读性整改版”没有真正覆盖到远端工作树。v0.7.1 不重新设计业务算法，而是把已经完成并通过 Host 门禁的目录、注释和交接规范固化为一次可直接替换的清洁工程包。

## 2. v0.7.1 目录要求

```text
app/
├─ inc/    只放应用层 .h
└─ src/    只放应用层 .c

board/     板级引脚、极性、ADC比例、Flash布局和安全门禁
driver/    目标芯片驱动
service/   ISR/回调/主循环服务桥接
docs/      编号文档、原理图和交接说明
project/   Keil AC6工程
tests/     Host回归测试，不进入目标镜像
tools/     架构/格式/Host/目标语法门禁，不进入目标镜像
vendor/    构建所需芯片库
```

发布包不包含 `.git/`、`.github/`、`.bootstrap/`、`tmp-probe.txt`、构建目录、旧MCU工程和 legacy 目录。

## 3. 可读性规则

- 首方函数定义统一使用 `Name / Input / Output / Description` 头注释；
- 复杂判断前写“为什么判断”，动作段写“为什么执行”；
- 统一 4 空格缩进，不使用 Tab；
- 文件级 `static` 变量、常量、函数声明与静态函数统一放在文件头区域；
- `app/inc/*.h` 的可调宏必须注明物理意义和单位；
- 参数先定义后使用，禁止在业务函数内散落不可解释的魔法数。

## 4. 安全边界

v0.7.1 继续保持：

```c
BOARD_POWER_OUTPUT_ALLOWED == 0
```

Host/静态检查通过不代表 COMP 极性、ADC比例、Flash物理行为、首脉冲或 300 W 台架已经验收。

## 5. 替换旧仓库的方法

推荐先备份当前工作区，然后保留 `.git/`，删除其余旧工程文件，再复制本包内容。不要把旧 `app/*.c` 与新 `app/src/*.c` 混合保留。

替换后必须确认：

```text
app/app.c                 不存在
app/app.h                 不存在
app/inc/app.h             存在
app/src/app.c             存在
tmp-probe.txt             不存在
.bootstrap/               不存在
```

然后运行：

```bash
python tools/run_checks.py
```
