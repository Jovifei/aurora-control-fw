# 24 · 300W 重构工程介绍

## 1. 工程目标

本工程不是对120W HT32代码的逐文件移植，而是把成熟产品行为迁移到新的300W单路异步Boost硬件，同时建立可换MCU的软件分层。

默认功率BOM为300W；低功率120W作为编译期Profile保留。Bootloader/OTA不属于当前APP范围。

## 2. 新硬件核心差异

- MCU：G32F031K8T，Cortex-M0+；
- 单路PWM：PA15 / GLC；
- 没有同步高侧PWM，不配置互补输出和死区；
- 没有BAT_I ADC；电池电流只能用PV功率、效率和BAT_U估算；
- COMP0负责MOS快速过流链，PB10 COMP0_OUT直接影响U6 EN；
- COMP2用于PV快速电流保护；
- Relay连接Boost母线与电池；
- 同时采样PV_I、PV_U、BAT_U、BST_U、MOS NTC、AMB NTC；
- 参数保存在片内Flash双页Journal。

## 3. 软件分层

```text
app/
  inc/ + src/
  ├─ measurement   ADC块换算、NTC、PV_I运行时零点
  ├─ charger       电池化学体系和TC/CC/CV/Float
  ├─ mppt          P-V搜索和PV参考电压PI
  ├─ protection    V2.7毫秒保护、OCP、温度和NTC
  ├─ power_stage   启动、预充、Relay、BAT稳定、Duty执行器
  ├─ protocol      旧UART协议兼容
  ├─ ui            RUN/FAULT显示
  └─ storage       参数格式与CRC

service/
  ISR邮箱、DMA块所有权、物理Relay/PWM仲裁、看门狗、Flash执行门禁

driver/
  inc/ + src/
  ADC/PWM/COMP/GPIO/UART/Flash/IWDT目标驱动

board/
  PinMap、比例、Flash地址、功率人工门禁

vendor/
  G32F031 CMSIS / Device / DDL
```

## 4. ADC与控制数据流

```text
ATMR固定周期触发ADC
→ 六通道规则扫描
→ DMA双半缓冲
→ ISR只发布完整块
→ Service主循环消费
→ measurement形成物理量快照
→ Protection / Charger / MPPT只读快照
```

APP任何使用处都不能重新触发ADC。

## 5. MPPT控制链

录音中的300W重构方向与当前结构一致：MPPT不直接写PWM，而是控制PV工作点。

```text
Vpv / Ipv / Ppv
   ↓
P-V斜率搜索
   ↓
Vpv_ref
   ↓
PV电压PI
   ↓
理论PV功率请求
   ↓
电池充电目标 + 温度 + PV电流 + 功率包络
   ↓
Power Stage执行器
   ↓
物理Duty
   ↓
CCR preload
   ↓
下一自然UEV生效
```

旧HT32闭源MPPT库不进入新工程。

## 6. 无BAT_I后的充电控制

`BAT_I_EST`始终标记为ESTIMATED：

```text
Ppv = Vpv × Ipv
Pbat_est = Ppv × η
Ibat_est = Pbat_est / Vbat
```

CC阶段采用：

```text
Vbat × I_target 前馈
+ Ibat_est低带宽反馈修正
→ 电池侧目标功率
→ / η
→ PV侧允许功率
```

CV阶段主要依赖真实BAT_U闭环。

## 7. Relay是启动安全的核心

必须牢记：**Relay不是一上电就闭合。**

```text
Relay OFF
→ 受限Boost把BST_U充起来
→ BST_U与BAT_U压差足够小并稳定
→ PWM先关闭
→ Relay ON
→ BAT_U完整10s稳定
→ 才允许RUN/MPPT
```

这个约束同时存在于Power Stage状态机和Service物理输出仲裁中。

## 8. 当前安全状态

即使Host测试全部通过，当前仍保持：

```c
BOARD_POWER_OUTPUT_ALLOWED == 0
```

只有COMP链、模拟标定、Keil AC6、低压台架和功率波形证据闭环后才能改变该门禁。
