# V0.9.0 收尾审计与阻塞项

> 分支：`codex/v0.9.0-analog-mature-behavior`
>
> 基线：`codex/v0.8.3-two-layer-architecture`
>
> 审计目标：对照 `V0.9.0 — Analog Acquisition & Mature Behavior Parity` 合同与旧 120W 成熟源码，区分“已经实现”“仍需软件收尾”“必须台架/硬件确认”。

## 1. 当前结论

V0.9.0 主体已经落地，但 **仍保持 Draft，不应合并**。当前最重要的状态如下：

- 3.3V ADC参考已经进入板级配置；
- PV_I 已去除旧 120W 的 2048 半电源零点默认值，候选极性改为 `+1`，并增加运行时零点质量门；
- NTC 已恢复旧 100K/B3950 166点表，Open/Short 物理方向已修正；
- BST_U 近满量程会撤销 BUS 有效位并阻止继电器误闭合；
- 铅酸温补、TC/CC/CV/Float 时间行为、PV_I 合理性诊断已大部分恢复；
- `BOARD_GATE_ANALOG_CALIBRATED=0`、`BOARD_POWER_OUTPUT_ALLOWED=0` 继续保持，台架未闭环前不允许实功率输出。

## 2. 已完成的软件项

### 2.1 NTC

已实现：

```text
ADC raw
  -> 先判 OPEN / SHORT
  -> 正常时计算 Rntc
  -> 166点表 + 插值
  -> 方向趋势滤波
  -> 保护读取显式 NTC status
```

物理语义：

```text
OPEN  -> ADC接近VDD/满量程
SHORT -> ADC接近GND/0 code
```

5V -> 3.3V 不需要重做温度表，因为 NTC 上拉和 ADC 参考同源，ADC 比值中 VDD 约掉。

### 2.2 PV_I

当前候选硬件模型：

```text
3mΩ shunt
  -> G32内部OPA ×16
  -> ADC 3.3V/12bit
```

理论数量级：

```text
1 code ≈ 16.79mA
12A ≈ 715 code
```

已经取消：

```text
zero = 2048
polarity = -1
```

改为：

```text
candidate zero = 0附近，由运行时校准覆盖
candidate polarity = +1
32个完整DMA块零点校准
mean/min/max/spread/连续有效窗口/最大尝试次数
```

注意：零点允许窗口当前仍是台架候选范围，**不是产品最终标定值**。不得仅凭 Host 测试把它改成“已校准”。

### 2.3 BST_U / Relay

当前 125K/5K 的 26:1 分压，在 3.3V ADC 下：

```text
82.2V -> 约3.162V，可测
87.2V -> 约3.354V，超3.3V
93.0V -> 约3.577V，明显超量程
```

软件已经执行 fail-safe：

```text
BST raw接近满量程
 -> BUS测量无效
 -> 置诊断/保护
 -> PRECHARGE不能通过必需测量门
 -> 饱和值绝不能满足 |BST-BAT| 压差闭合条件
```

这只能防误动作，**不能修复硬件量程**。BST_U 分压仍为 P0 硬件整改/确认项。

### 2.4 铅酸温补

已恢复：

```text
参考 25°C
-3mV / °C / 2V-cell
-20~55°C 温度钳位
48/60/72V -> 24/30/36 cells
```

温补作用于 CV/Float/Full 及慢/中速软件过压参考；Fast OV 与 93V absolute 不随温度漂移。

### 2.5 成熟时序

已实现：

- TC -> CC：约 110ms；
- CC -> CV：按越压程度 +1/+2/+6 加权；
- CV 尾流判满：约 1s；
- Lead CV -> Float：先停止能量传输，等待电池自然下降到 Float 窗口中点；
- Float 低电流结束：约 60s；
- Float 总时长：180min；
- 总充电时长：900min；
- Recharge 资格：约 1s。

## 3. 本轮审计发现的三个软件收尾项

### 3.1 CV -> CC 缺少“控制稳定”门

旧 120W 不是单纯：

```text
Vbat < CV目标 - 0.5V
持续约110ms
```

还要求闭源库处于：

```text
Mppt_process == 2
```

当前 300W 新架构没有同名黑盒状态，因此不能机械复制变量；应建立明确的等价门。建议至少满足：

```text
!weak_light
&& !thermal_limited
&& !input_limited
```

避免 PV 能量不足或温度/输入包络主动限功率时，仅因为电池电压被拉低就误退回 CC。

### 3.2 Float 低压 12s 不能在 RUN 中直接切 CC

旧 120W 的成熟语义是：

```text
Float已启动
Vbat < Float_Min 持续约12s
 -> 主Boost退出
 -> 宏状态回 init
 -> 后续重新经过准入/稳定性检查
```

当前 V0.9.0 是直接 `FLOAT -> CC`，会跳过重新启动语义。

新架构建议：

```text
Charger仍可重新选择CC阶段
但必须同时产生“charge-cycle restart”事件
PowerStage立即Duty=0
保持/重新确认继电器安全状态
重新跑 BAT stability 后才回 RUN
```

普通 Float 维持失败不应被误写成“传感器故障级重新校零”；是否重跑 PV_I zero-cal 与是否打开继电器应由功率级安全策略明确决定。

### 3.3 Complete -> Recharge 1s 同样需要重新启动准入

旧 120W：

```text
Complete
Vbat < Recharge 持续约1s
 -> 回 init
 -> 再决定 TC / CC
```

当前 V0.9.0 直接 `COMPLETE -> CC`。虽然现有 12 组档案的 Recharge 电压均高于 Trickle Exit，实际阶段通常仍会落在 CC，但 **缺失的是启动准入，不只是阶段枚举值**。

新架构应与 3.2 共用一次性 `charge-cycle restart` 事件，避免直接沿用旧 MPPT/PowerStage 运行上下文。

## 4. PV_I 合理性故障的恢复边界

这类故障与普通充电复充不同。

已经实现的检测：

```text
PWM ON：明显负向PV_I持续约10ms
 -> polarity/sensor plausibility fault

PWM OFF：|PV_I|仍很大持续约1.5s
 -> zero/OPA/sensor plausibility fault
```

这类故障恢复后必须：

```text
重新PV_I零点校准
 -> 重新走功率级安全启动
 -> 再允许主Boost
```

不能只清 fault bit 后直接沿用旧 Duty/PI/MPPT 状态。

## 5. P0 台架/硬件门禁

在以下项目全部通过前，Power Output 继续 LOCKED：

1. BST_U 分压/BOM量程确认；
2. PV_I 正向极性实测确认；
3. PV_I 零点均值、spread、温漂、重复性冻结；
4. 内部 OPA ×16 共模/输出摆幅与 12A 量级验证；
5. COMP -> Break -> MOE -> 实际栅极关断全链路验证。

P1：

- BAT_U 15M/510K 高源阻抗下的采样建立、漏电与温漂；
- NTC 电阻箱 -40/25/95/105/125°C + Open/Short。

## 6. 不在 V0.9.0 伪实现的 parity gap

### 6.1 BAT 反向电流

300W 新板没有真实 BAT_I 通道。不能用 PV 功率/电池电压估算值伪装成微秒/毫秒级反向电流硬保护。

### 6.2 真正 24h 滚动能量

旧 120W 有 49 点/30min 的 Flash 历史。300W 当前内部 Flash 架构下，直接照搬会引入写寿命风险。后续单独设计：

```text
RAM rolling window
+ 低频持久化
+ wear leveling
```

## 7. V0.9.0 完成定义

V0.9.0 只有同时满足以下条件才可从 Draft 进入可合并状态：

- 软件收尾 3 项闭环并增加回归；
- Workbook/文档/源码参数一致；
- Host/CI 全绿；
- 5 个 P0 台架项有实测记录；
- 功率门禁由“实测证据”解锁，而不是由代码默认值解锁；
- PR 合并前再次核对 `BOARD_GATE_ANALOG_CALIBRATED` 和 `BOARD_POWER_OUTPUT_ALLOWED` 的发布策略。
