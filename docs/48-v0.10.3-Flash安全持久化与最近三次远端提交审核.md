## 2. 与120W模拟EEPROM旧失效模式的对照

120W旧实现的高风险链条是：Init失败或页满后活动地址保持BSS零值，随后未校验地把数据写到`0x00000000`，可能破坏IAP/向量表。

300W当前架构已经具备两层基础隔离：

1. Scatter把应用区限制到`0x00000000~0x0000FBFF`，最后1KiB独立留给A/B Journal；
2. `drv_flash`只接受`0xFC00~0xFFFF`保留区，地址0直接拒绝。

因此不迁移120W的活动地址式EEPROM仿真，而是在现有双页Journal上继续加固。

## 3. 本轮发现并关闭的两个关键风险

### 3.1 写失败前提前递增sequence

旧`runtime_storage()`在真正擦写前先`sequence++`，再按奇偶选择页。第一次写失败后RAM sequence已经变化，下一轮可能切换到另一页，存在把上一份有效页也擦掉的放大风险。

修复后：

- 使用`staged.sequence = committed.sequence + 1`；
- 永远只写`active_page`的另一页；
- I/O失败只在同一个备用页重试一次；
- Commit + 整页回读 + CRC/内容/sequence验证全部成功后，才更新RAM中的`sequence`和`active_page`；
- 两次真实失败后`write_inhibited=true`，本会话不再反复擦页。

### 3.2 欠压/掉电边沿仍可能进入Flash擦写

旧门禁只要求PWM OFF、Relay OFF、dirty满1s。Demo/弱光场景下，即使系统正在接近brownout，只要这三个条件碰巧满足，仍可能开始擦页。

修复后：

- 物理写只允许`OFF / WAIT_PV / NO_SUN / FAULT`稳定停机态；
- 启动、预充、Relay握手、RUN阶段只在RAM里置dirty；
- PVD正常启动后保留为只读监测，IRQ/Reset继续关闭；
- PVD/VDD不合格只**拒绝**本次Flash写，绝不触发“欠压保存”；
- Driver层再次检查VDD资格，避免未来其他调用者绕过Runtime策略。

## 4. 地址与双页边界

`drv_flash_program()`现在要求一次请求完整落在单个512字节页内。即使未来出现offset/length计算错误，也不能用一次program跨越A/B两个冗余页，更不能写到地址0。

## 5. 数据保持边界

该策略选择“宁可丢最后一段RAM统计，也不能在brownout里赌一次Flash写”。若产品以后要求严格掉电保存，应通过可验证的保持电容 + 提前量，或FRAM/MRAM解决，而不是重新引入LVD/PVD中断写Flash。

## 6. 发布边界

本轮属于软件持久化安全修复。它不能证明Flash供电门限、掉电斜率和实板保持时间已经通过硬件验证；生产功率门仍保持原状态。
