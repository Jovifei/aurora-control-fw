# v0.10.2 · 120W → 300W 功能移植审核报告

## 1. 审核范围与结论

| 项目 | 内容 |
|---|---|
| 审核对象 | `aurora-control-fw` v0.10.2（`main` 约 `a862229`） |
| 120W 行为基线 | `docs/22-REF-120W-V2.7行为与参数基线.md`、`docs/23-120W到300W行为迁移矩阵.md` |
| 新硬件基线 | `docs/14-REF-硬件原理图-V0.1.pdf`（C300_MPPT Boost V0.1，G32F031K8T LQFP32） |
| Host 验证 | `python tools/run_checks.py`：Architecture / Code style / 24 项合同测试 PASS |
| Keil 验证 | 本机 AC6 Rebuild 0 Error / 0 Warning；**不等于** `BOARD_GATE_KEIL_LINKED=1` |

### 1.1 总判

**软件行为骨架已按新硬件落地，功率尚未放行。**

点名功能（弱光等待、充电状态机、12 组电池、Demo、ADC、单路 PWM、软硬件保护、自研 MPPT）在源码里都有，并且已经按「有继电器、无 BAT_I、无同步管」改写，**不是**把 120W 原样搬过来。

同时，下列门禁在 `driver/inc/board_config.h` 中**全部为 0**：

```c
BOARD_GATE_COMP_ROUTE_VALIDATED      (0U)
BOARD_GATE_ANALOG_CALIBRATED         (0U)
BOARD_GATE_KEIL_LINKED               (0U)
BOARD_GATE_LOW_VOLTAGE_BENCH         (0U)
BOARD_GATE_DEMO_LOAD_VALIDATED       (0U)
BOARD_POWER_OUTPUT_ALLOWED           (0U)
```

因此本版本是**可编译的软件候选基线**，不是已验收的 300W 产品，也不能写成「移植并闭环」。

### 1.2 措辞边界

| 说法 | 是否成立 |
|---|---|
| 软件逻辑/状态机/时序已写入源码 | 成立 |
| Host 架构与合同测试通过 | 成立 |
| 硬件 COMP / 模拟标定 / 继电器 / 功率 SOA 已验收 | **不成立** |
| 120W 全部硬件能力已等价移植 | **不成立**（见第 4 节） |

## 2. 逐功能审核

### 2.1 弱光 / MCU 供电稳定再启动（PVD 资格准入）

| 项 | 结论 |
|---|---|
| 实现状态 | **软件完成** |
| 关键文件 | `driver/src/drv_system.c`、`app/src/main.c` |

**已实现：**

1. `main()` 先做 GPIO 安全态（Relay/LINK/LED 关闭），再调用 `drv_system_wait_for_supply_stable()`；
2. PVD 候选门限 `BOARD_MCU_PVD_THRESHOLD_MV = 2800`，50µs 硬件数字滤波；
3. 编译期硬禁令：`BOARD_MCU_PVD_RESET_ENABLE=0`、`BOARD_MCU_PVD_IRQ_ENABLE=0`，违反则 `#error`；
4. VDD 跌落时**立即清零**连续稳定计时，必须连续高于 VPVD **满 100ms**；
5. 等待期间使用 `__WFI()`，不产生软件 Fault；
6. PVD 通过前**不初始化** IWDT / PWM / COMP / ADC / UART 业务链。

**待台架确认：** 2.8V / 100ms 仍是候选值，需结合辅助电源与弱光实测冻结。

### 2.2 ADC 采样与测量

| 项 | 结论 |
|---|---|
| 实现状态 | **按新硬件改写；模拟标定未放行** |
| 关键文件 | `driver/src/drv_adc.c`、`app/src/measurement.c`、`driver/inc/board_config.h` |

**已实现：**

| 通道 | 引脚 | 用途 |
|---|---|---|
| CH1 | PA8 | PV_I（3mΩ × 内部 OPA×16） |
| CH2 | PA9 | PV_U（75k/3k，比例 26） |
| CH3 | PB0 | BAT_U（15M/510k） |
| CH4 | PB1 | BST_U（125k/5k，比例 26） |
| CH5 | PB12 | NTC_MOS（5.1k + 100K/B3950） |
| CH6 | PB5 | NTC_AMB（同 MOS 探头特性） |

**PV_I 零点：**

- 内部 OPA 配置为 AVDD/2 共模（约 1.65V），名义零点 **2048** 码，极性候选 **+1**；
- 启动时在 PWM/Relay 关闭下采集 **32 个完整 DMA 块**，单块噪声 ≤16 码、跨块漂移 ≤16 码；
- 校准窗约 1280..2816。

**NTC：** 166 点查表；开路 ≥4093、短路 ≤64；10ms × 10 次同向趋势滤波。

**BST_U 防呆：** ADC 码 ≥4080 判饱和，撤销 BUS 有效位，阻止 Relay 误闭合。

**BAT_I：** 新板无硬件通道；`measurement.c` 用 Ppv×η/Vbat **估算**，质量位 `ESTIMATED`，不伪造瞬态硬件电流。

**风险：** 26:1 分压 + 3.3V 参考满量程约 **85.8V**；72V 铅酸 CV 87.0V / Fast OV 91V 会触发近满量程拒绝（见第 5 节 P0）。

### 2.3 PWM 发波与功率级安全门控

| 项 | 结论 |
|---|---|
| 实现状态 | **按新硬件改写；功率总门锁定** |
| 关键文件 | `driver/src/drv_pwm.c`、`app/src/main.c`、`app/src/power_stage.c` |

**已实现：**

1. **拓扑：** 50kHz 单路异步 Boost，仅 GLC（PA15 / ATMR_CH0）；GHC（PA14）禁用并保持低电平；
2. **Preload 与自然 UEV：** CCR/ARR 均 Preload，运行期禁止软件 UG，只在自然 UEV 边界生效；
3. **首次发波门控：** 0 Duty → 等待自然 UEV 确认 → 经 epoch / Break 实时源 / Break 锁存 / 板级总门（及 Demo 门）复核 → 再开 MOE；
4. **Automatic Output 关闭：** Break 解除后禁止硬件自动恢复 MOE；
5. **`safety_still_clear()`：** 运行层在真正放行 PWM 前后多次复核安全 epoch、故障、Break 和门禁。

**当前状态：** `BOARD_POWER_OUTPUT_ALLOWED=0`，固件**不会**真正放行功率输出。

### 2.4 继电器预充与安全闭合（Battery 路径）

| 项 | 结论 |
|---|---|
| 实现状态 | **软件完成（硬约束已写入）** |
| 关键文件 | `app/src/power_stage.c`、`app/src/main.c` |

**执行顺序（任何改动不得破坏）：**

```text
Relay OFF
→ Boost 受限升压 BST_U
→ |BST_U − BAT_U| ≤ 1.5V 连续 1s
→ Duty 归 0 / 运行层物理关 PWM
→ relay_close_still_safe() 实时二次复核
→ Relay ON
→ 100ms 机械稳定
→ 复核压差 ≤ 2.5V
→ PWM 保持 OFF，观察 BAT_U 10s（max−min ≤ 2V）
→ 进入 RUN
```

**Demo 路径差异：** 确认输出端无外部有源电压（>5V 拒绝）后，直接吸合 Relay 再低功率探测；**不走** Battery 均压预充。这是无电池模式的刻意设计，不是 Battery 路径回归。

### 2.5 充电全过程（TC / CC / CV / Float / Complete / Recharge）

| 项 | 结论 |
|---|---|
| 实现状态 | **软件完成（无 BAT_I 改写）** |
| 关键文件 | `app/src/charger.c`、`app/inc/app_config.h` |

| 转移 / 行为 | 参数 |
|---|---|
| TC → CC | V ≥ trickle_exit 持续 **110ms** |
| CC → CV | 加权积分：基础 +1、超驱 +1/+4，**score > 10** 进入 CV |
| CV → CC | V < CV − 500mV 持续 **110ms**，且 `!weak_light && !thermal && !input_limited` |
| CV 尾流判满 | 尾流电流持续 **1s** |
| Float 进入（铅酸） | CV 结束后电压回落到 Float 中点，持续 **110ms** |
| Float 时限 | **180min**，同样只计真实传能 |
| Float 低压复充 | 12s 触发 `request_restart` |
| Complete 复充 | 1s 触发 `request_restart` |
| 复充后功率级 | 回 `BAT_STABILITY` 重新 10s 稳定，**不**重新做 PV_I 零点校准 |
| 总充电时限 | **900min**，只在 `actual_power_transfer` 为真时累计 |

**`actual_power_transfer` 判据：** Battery 模式 + RUN + Relay + 物理 PWM + Charger 许可 + PV 功率 ≥ 门槛。

**差异：** 档案 `cc_current_ma = 3000` 仍是 **120W 的 3A**，未按 300W 重标定。

### 2.6 多种类电池支持与铅酸温补

| 项 | 结论 |
|---|---|
| 实现状态 | **软件完成** |
| 关键文件 | `app/src/charger.c`、`app/inc/app_config.h` |

**12 组档案：** 铅酸 / 三元锂 / 磷酸铁锂 / 钠离子 × 48V / 60V / 72V。

**低温禁充：**

### 2.7 Demo 无电池带载模式

| 项 | 结论 |
|---|---|
| 实现状态 | **软件候选；Demo 台架门 = 0** |
| 关键文件 | `app/src/power_stage.c`、`app/src/main.c`、`docs/42-v0.10.2-Demo无电池带载模式与安全边界.md` |

**状态机：**

1. **外部有源检测：** BAT_U > 5V → 拒绝启动并锁存 `AURORA_FAULT_DEMO_OUTPUT`；
2. **DEMO_PROBE：** 5W 受限功率发波，Pv ≥ 2W 持续 1.5s 确认负载，5s 超时无负载 → `NO_SUN`；
3. **DEMO_RUN：** 默认 48V CV、30W 功率上限；过载 100ms 退出；
4. **门禁隔离：** `drv_board_demo_load_gate_open()` 只约束 Demo 模式，**不**并进总功率门。

**注意：** 默认 30W，但协议可通过 `demo_power_limit_mw` 配置到额定功率（300W）；步进器只在 0 或超过额定上限时才打回 30W。无输出电流传感器，**不能**宣称恒流能力。

### 2.8 及时保护与硬件保护

| 项 | 结论 |
|---|---|
| 实现状态 | **软件结构已移植；COMP 路由未验收** |
| 关键文件 | `driver/src/drv_comp.c`、`app/src/protection.c`、`app/src/interrupts.c` |

**硬件保护网络：**

| 路径 | 作用 |
|---|---|
| COMP0（MOS 分流 vs PA7） | PB10 开漏拉低 U6 EN + ATMR Break（低有效） |
| COMP2（PV 快比） | COMP1_2_3 中断，与 COMP0、Break 同为 NVIC 优先级 0 |
| ISR 第一动作 | `drv_pwm_force_off_isr()` 物理关 PWM |

**ISR 与 epoch：** `force_off` 每次都会执行；`safety_epoch++` 只在 **PWM 当时已在输出** 时才递增。未发波时 COMP 只记诊断（`startup_comp_ignored_count`），不软件锁存 OCP——这是 V1.12.19 启动瞬态语义的有意实现。

**软件分级保护（节选）：**

| 保护项 | 阈值 / 时序 |
|---|---|
| PV UV/OV | 8V/1s、9V/1s；55V/1s、54V/1s |
| PV OCP | 1.2×/10s、1.35×/1s、1.5×/100ms |
| 过功率 | 额定×1.2 / 5s（300W 候选 360W） |
| BAT 多级 OV | 5s / +0.7V 1s / 3ms 快层 / 93V 1s |
| MOS 温度 | 95°C 降额、104°C 末端、105°C/1s 保护、95°C/1s 恢复 |
| 环境温 | 55/50°C；锂电 0/+5°C；铅酸/钠 -20/-15°C |
| PV_I 合理性 | 发波期 ≤−1A/10ms；关波期 ≥3A/1.5s |
| 30min 无光 | PV < 13V 且 MPPT 无效连续 30min → 断 Relay / Link |

**不存在：** 电池反向电流硬件检测（新板无 BAT_I）。

### 2.9 MPPT 计算与控制链

| 项 | 结论 |
|---|---|
| 实现状态 | **软件完成（自研替代闭源库）** |
| 关键文件 | `app/src/mppt.c`、`app/src/power_stage.c` |

1. **双时间尺度：** 80ms 外层 Vpv_ref 搜索 + 10ms 内层电压 PI 功率控制；
2. **自适应步长：** 依据 |ΔP/ΔV| 在 50~500mV 间调整；
3. **噪声死区：** |ΔV| < 50mV 或 |ΔP| < 500mW 时冻结参考；
4. **外部限功率时冻结搜索**，避免把限幅误判为 MPP；
5. **Fast Descent：** 开路后以 500mV 步长快速下探；
6. **Duty 执行：** MPPT/Charger 只出功率命令，`power_stage` 前馈+PI+斜率限制转 Q15 占空比，业务不写 CCR。

## 3. 新板硬件差异与非等价项

| 旧 120W 能力 | 300W G32F031 新板 | 软件处理 |
|---|---|---|
| BAT_I 独立 ADC | **无** | Ppv×η/Vbat 估算，标识 `ESTIMATED` |

| OTA / IAP | 本版本范围外 | 未移植 |

## 4. 对「全部完整闭环」表述的复核

另一份审查稿在机制描述上大多正确，但总标题「完整移植并闭环」**过满**。下表为源码核对后的修正。

### 4.1 同意保留的表述

- PVD 弱光等待、`__WFI()`、外设延迟初始化；
- 继电器 Battery 七步顺序；
- 充电 TC/CC/CV/Float 时序与 15h 真实传能计时；
- 12 组档案、锂电 0/+5°C、铅酸温补；
- 新板正确未移植项（无 BAT_I、无同步管、无负电流）；
- Host 检查通过与功率总门保持 0。

### 4.2 需要收紧的表述

| 对方表述 | 源码事实 |
|---|---|
| 「完整移植并闭环」 | 六个门禁均为 0；Host PASS ≠ 硬件闭环 |
| ADC/PWM/Demo/COMP「完整实现」 | 软件已接线 ≠ 极性/增益/Break→Vgs/拉弧已验收 |
| Demo「严格限制 30W」 | 默认 30W；协议可配到额定功率 |
| 「5 项 P0 台架」 | 代码门禁实际为 **6 个 0** |
| ISR「关 PWM 并自增 epoch」 | epoch 仅在 PWM 已输出时递增 |
| 未提及 CC 3A | 充电电流未按 300W 重标定（docs/32 zero 矛盾已在本批修正） |

## 5. 台架放行前 P0 确认项

在下列证据齐全前，`BOARD_POWER_OUTPUT_ALLOWED` 及关联门禁**必须保持 0**：

| 优先级 | 确认项 | 原因 |
|---|---|---|
| P0 | **BST_U 26:1 分压量程** | 3.3V ADC 满量程约 85.8V；72V 平台 87.2V/93V 存在超量程风险 |
| P0 | **PV_I 极性、零点、增益、温漂** | 内部 OPA×16 + AVDD/2 共模；2048 为候选，需实板冻结 |
| P0 | **COMP → Break → U6 EN → Vgs 波形** | 示波器验证 MOS 栅极关断延时与极性 |
| P0 | **Relay 触点均压与拉弧** | 1.5V 压差合闸、100ms/2.5V 复核需实板证据 |
| P0 | **六项代码门禁** | COMP / ANALOG / KEIL / LOW_VOLTAGE / DEMO / POWER 均为 0 |
| P1 | **300W SOA 参数冻结** | PV 12A、过功率 360W、95~104°C 降额末端 9W 仍为候选 |
| P1 | **充电电流重标定** | 若产品需要 >3A CC，需单独参数与台架，不是移植遗漏 |

## 6. 审核结论摘要

```text
┌─────────────────────────────────────────────────────────────┐
│  120W V2.7 成熟行为  →  300W G32F031 新硬件                │
│                                                             │
│  软件：状态机 / 时序 / 保护结构 / 自研 MPPT  →  已写入源码   │
│  硬件：COMP / 标定 / Relay / SOA / 功率输出  →  未放行       │
│                                                             │
│  可宣称：v0.10.2 软件候选基线，Keil 可编，Host 合同 PASS    │
│  不可宣称：300W 实功率已验收、移植已闭环、Demo 已台架放行    │
└─────────────────────────────────────────────────────────────┘
```

**下一步建议：**

1. 按第 5 节 P0 清单做示波器与低压台架验收；
2. 确认 BST_U 分压 BOM 是否需调整（参见 `docs/35`）；
3. 仅在 MAP + 示波器 + 继电器波形证据齐全后，逐项将对应 `BOARD_GATE_*` 改为 1。
