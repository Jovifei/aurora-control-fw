## 2. v0.10.2 已经真实落地的基础能力

下列基础功能并未被 v0.10.3 推翻：

- PVD 弱光供电资格与外设延迟初始化；
- 六通道 ADC 定时触发、DMA 双块、完整测量快照；
- PV_I AVDD/2 共模、名义 2048 码与运行时零点校准；
- 100K/B3950 NTC、开短路检测、方向滤波；
- 12 组电池档案、TC/CC/CV/Float/Complete/Recharge；
- 铅酸温补与分体系低温禁充；
- 80ms MPPT 搜索、10ms PV 电压 PI、统一 Duty 执行器；
- 单路异步 Boost、CCR/ARR preload、自然 UEV、AOE 关闭；
- PV/BAT/BUS/温度/传感器保护；
- Flash Journal v3、双能量账本、49 点滚动 24h 历史；
- 旧 30 字节遥测、设置、能量复位与 LED 兼容路径。

这些属于“软件结构已经写入源码”，不代表模拟增益、COMP 极性、Relay 触点或功率 SOA 已经由实板证明。

## 3. v0.10.2 缺陷与 v0.10.3 处理结果

| v0.10.2 审计发现 | v0.10.3 当前处理 | 状态 |
|---|---|---|
| 硬件 Break 先清 MOE 后，ISR 读取 `drv_pwm_output_active()` 可能把运行 OCP 当成启动瞬态 | 增加软件 PWM ARM 状态；在 `drv_pwm_arm()` 前发布 `ACTIVE`；`WAIT_ZERO` 仍按启动瞬态处理 | **已修复** |
| Relay 闭合前可能继续使用关波前的旧 BUS/BAT 快照 | 增加 `AURORA_POWER_RELAY_HOLD_OFF`；PWM 关闭、保持 Relay OFF、等待 20ms 和更新的 ADC 序号后再复核 | **已修复** |
| PowerStage 内部认为 Relay 已闭合，但 Runtime 可能拒绝 GPIO 写出 | `aurora_power_stage_step_ex()` 接收 `relay_applied`；未落实时不开始 100ms、不进 BAT_STABILITY/RUN 或 Demo Probe | **已修复** |
| Demo Relay 被 Battery 专用状态/均压条件永久拒绝 | Runtime 按 Battery/Demo 分模式仲裁；Demo 不使用 `BST_U≈BAT_U` 条件 | **已修复** |
| Demo 默认 30W，但协议可配置到 300W | 协议、旧 Flash 清洗和运行时三层统一限制为不可绕过的 30W | **已修复** |
| PRECHARGE 超时可能因低 Ppv 被误判为 `PV_WEAK`，形成无限重试 | 已进入 PRECHARGE 且 PV 电压仍合格时，固定归类 `BUS_PRECHARGE_TIMEOUT` | **已修复** |
| `precharge_failure_count` 成功后未清零 | 只有 Relay 已落实、100ms 到期且闭合后 2.5V 压差复核成功时才清零 | **已修复** |
| ADC 停止后最后一帧正功率可能继续累计 PV 能量 | 能量累计要求 valid、sequence、≤50ms、新鲜 ADC、无 stale/DMA/overrun 且物理 PWM 输出 | **已修复** |
| v0.10.2 新功能只有字符串合同，缺少关键行为回归 | 新增独立 `aurora_v0103_tests`，保留原有 Host/Debug Host 回归 | **已修复** |
| 旧遥测能量字段物理语义存在争议 | 本轮按产品裁决保持旧 30 字节布局和当前 PV 实测语义，不静默改字段；电池侧估算账本仍存 Flash v3 | **本轮冻结** |
| v0.10.3 Keil/MAP 尚无新证据 | 不复用 v0.10.2 的日志冒充本轮结果，门禁继续为 0 | **待目标工具链** |

## 4. 当前快速故障与 PWM 授权语义

v0.10.3 使用三态最小模型：

```text
ARM_OFF
    未申请发波

ARM_WAIT_ZERO
    已提交零 CCR，等待自然 UEV
    发生 COMP/Break 只记录启动诊断，不自动等同运行 OCP

ARM_ACTIVE
    已进入 MOE 申请窗口或已经输出
    任何 COMP/Break 都按运行期快速故障锁存
```

关键顺序：

```text
最终安全复核
→ pwm_arm_state = ACTIVE
→ drv_pwm_arm()
→ 硬件允许输出
```

因此真实硬件即使先由 Break 清除 MOE，随后进入 ISR，软件仍能依据故障前的授权状态锁存故障，而不是读取故障后的 MOE 状态进行错误分类。

## 5. 当前 Battery Relay 安全顺序

```text
Relay OFF
→ 受限 Boost 建立 BST_U
→ |BST_U-BAT_U| ≤ 1.5V 连续 1s
→ RELAY_HOLD_OFF：Duty=0、PWM命令OFF、Relay保持OFF
→ 等待20ms放能窗口
→ 等待更新的ADC快照
→ 再确认BUS有效、未饱和、未过压、压差仍≤1.5V
→ 请求Relay闭合
→ Runtime真正写出Relay GPIO
→ PowerStage看到relay_applied=true后开始100ms机械稳定
→ 闭合后压差≤2.5V
→ 清预充/Relay本会话失败计数
→ PWM保持OFF，BAT_U稳定10s（max-min≤2V）
→ RUN
```

`relay_applied` 只表示 GPIO 命令已经写出，不表示机械触点反馈。当前 PCB 没有 Relay 辅助触点，触点路径只能通过机械等待、压差和后续稳定窗口间接验证。

## 6. 当前 Demo 路径

```text
等待PV
→ PV_I零点校准
→ 输出端外部有源检测
→ RELAY_HOLD_OFF：关PWM、20ms、更新ADC
→ Demo专属Runtime复核
→ Relay GPIO落实
→ 100ms机械等待
→ 5W Probe
→ 负载证据成立
→ 受限Demo RUN，最大30W
```

Demo 不进行 Battery 均压。当前只能描述为：

```text
受限恒压输出
PV输入侧功率/电流限制
规定且经过验证的无源负载
```

不能描述为真实恒流、任意负载电源或电池模拟器。

## 7. 充电、能量与协议边界

### 7.1 真实传输资格

15h、Float 180min 和电池侧估算能量要求：

```text
Battery模式
PowerStage == RUN
Runtime已写Relay GPIO
物理PWM正在输出
Charger允许充电
PV功率样本有效且新鲜
Ppv达到有效传输门槛
```

它仍是 `QUALIFIED / ESTIMATED` 证据，不等于 BAT_I 独立实测。

### 7.2 两套能量账本

- `lifetime_energy_wh / daily_energy_wh`：PV 输入侧实测功率积分；
- `charge_est_*`：按 `Ppv × η` 估算的电池侧充电能量；
- Flash v3 同时保存两套累计、余数和 49 点历史；
- v0.10.3 不修改旧 30 字节遥测帧长度和当前字段映射。

### 7.3 掉电限制

运行中 Flash 擦写仍要求 PWM OFF 且 Relay OFF。若外部供电突然完全消失，软件不能保证保存本次连续运行的全部增量。严格掉电保存仍需要 PVD 提前量与保持电容、FRAM/MRAM 或其他硬件方案。

## 8. 120W 功能的非等价项

| 旧 120W 能力 | 当前 300W 新板 | 结论 |
|---|---|---|
| BAT_I 独立 ADC | 无 | 只能估算，不等价 |
| BAT 反向电流快速比较器 | 无 | 软件不能伪造 |
| Q5 同步整流 | 单管异步 Boost | 不适用 |
| Q9/Q11 背靠背负极 MOS | 无 | 用 BUS 均压 + Relay 替代安全目标 |
| 独立硬件 BAT OVP | 无 | 仅有软件多级 OV，不等价 |
| HT32 闭源 MPPT 库 | MCU/架构已更换 | 自研 P-V 搜索替代 |
| OTA / IAP | 产品阶段明确不移植 | `NOT_MIGRATED_BY_PRODUCT_DECISION` |

## 9. 72V、高功率与板级阻塞

### 9.1 BST_U 量程

当前 BST_U 分压约 26:1，3.3V ADC 理论满量程约 85.8V；部分 72V 高 SOC 目标、87V 级 CV 与 93V 绝对保护超出或逼近量程。软件采用近满量程 fail-safe，不能靠换算系数恢复丢失的测量余量。

### 9.2 300W 参数

当前存在：

```text
额定软件上限300W
PV候选限流12A
电池CC目标3A
低压输入功率包络
95~104°C温度降额
```

这些参数不是“所有平台都已经实现300W”的证据。300W 产品定义、器件/电感/二极管/PCB/温升/SOA 和各电池平台的输出能力必须由独立台架版本冻结。

## 10. 功率门与验收清单

当前必须继续保持：

```c
BOARD_GATE_COMP_ROUTE_VALIDATED == 0
BOARD_GATE_ANALOG_CALIBRATED    == 0
BOARD_GATE_KEIL_LINKED          == 0
BOARD_GATE_LOW_VOLTAGE_BENCH    == 0
BOARD_GATE_DEMO_LOAD_VALIDATED  == 0
BOARD_POWER_OUTPUT_ALLOWED      == 0
```

解除前至少需要：

1. PV_I 0A/2A/6A/12A 的零点、方向、增益、线性和温漂；
2. BST_U/BAT_U 量程、饱和与误差；
3. COMP→Break→U6 EN→GLC/Vgs 的极性与关断延时；
4. Break 持续有效时无法重开 PWM；
5. Battery Relay 关波、20ms、ADC、触点拉弧与二次压差；
6. Demo 外部电源、空载、阻性、纯电容、电子负载、短路和卸载；
7. Keil ARMCLANG 链接、HEX/AXF/MAP 和 Flash Journal 地址；
8. 低压限流逐级升功率和 300W 热/SOA。
