# 02 · 软件分层与依赖规则

## 1. 单向依赖

```text
Application → Driver Interface → Chip/Board Driver
                              ↘ Vendor
```

- `app/inc`和`app/src`处理业务状态机、应用运行时和控制目标，可通过驱动契约调用Driver；
- `app/src/main.c`集中应用入口、事件邮箱、主循环调度、最终安全复查和功率提交；`app/src/interrupts.c`只做轻量中断桥接；
- `driver/`实现外设语义和板级PinMap、有效电平、分压比例、Flash地址及人工放行门禁，不反向包含APP；
- `vendor/`只提供CMSIS、器件定义和实际使用的DDL。

## 2. APP目录规则

```text
app/inc/*.h
app/src/*.c
```

`app/`根目录不得再放 `.c/.h`。公共类型在 `app_types.h`，应用可调参数在 `app_config.h`；模块私有 `static` 常量、变量和函数必须放在对应 `.c` 文件头。

## 3. 功能边界

| 模块 | 只允许做什么 | 明确禁止 |
|---|---|---|
| measurement | 完整DMA块滤波、标定、物理量快照、BAT_I估算、PV_I零点校准 | 发波、保护锁存、充电状态切换 |
| mppt | 更新Vpv_ref并计算理论功率 | 直接改Duty/CCR |
| charger | TC/CC/CV/Float、温补和电池功率上限 | 访问ADC或GPIO |
| protection | 软件多级阈值、去抖、active/latched故障管理 | 恢复PWM |
| power_stage | 启动退避、预充、继电器、Duty目标和状态机 | 写寄存器 |
| interrupts | 中断向量桥接、快速关波与轻量事件投递 | 在ISR中执行MPPT/充电/Flash等重业务 |
| main / runtime | 事件分发、主循环调度、最终安全复查、驱动提交与看门狗健康监督 | 绕过安全复核直接发波 |
| driver | 外设配置和最小ISR接口、板级PinMap与安全配置 | 包含APP业务头文件或业务逻辑 |

## 4. 自动门禁

`tools/check_architecture.py`拒绝：

- APP包含G32/CMSIS/DDL芯片头文件或访问GPIO、ATMR、DMA、COMP、NVIC；应用组合根可以包含Driver契约；
- Driver反向依赖业务层；
- APP或Driver不是 `inc/src` 布局，或重新出现Service/Board产品层；
- `legacy_*`、旧闭源库、BAT_S1/BAT_S2、`.bootstrap`、JSON或重复tests/tools；
- APP直接操作目标PWM寄存器；
- 运行期软件UPDATE、AOE自动恢复或未启用CCR preload；
- 最终PinMap和功率总门被静默修改。

`tools/check_code_style.py`拒绝：

- 函数缺少统一头注释；
- Tab或行尾空白；
- `static`或文件级宏出现在首个公开函数之后；
- 头文件宏没有用途说明；
- APP源码未放入 `inc/src`。
