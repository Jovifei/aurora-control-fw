# 02 · 软件分层与依赖规则

## 1. 单向依赖

```text
Application → Service → Driver Interface → Chip Driver
                         ↘ Board / Vendor
```

- `app/inc`和`app/src`只处理物理量、状态机和控制目标，不认识端口、通道、寄存器或芯片库；
- `service/`是唯一桥梁：ISR发布事件，主循环调用APP；APP输出逻辑命令，Service再调用驱动；
- `driver/`只实现外设语义，不认识MPPT、充电阶段或电池体系；
- `board/`保存PinMap、有效电平、分压比例、Flash地址和人工放行门禁；
- `vendor/`只提供CMSIS、器件定义和实际使用的DDL。

## 2. APP目录规则

```text
app/inc/*.h
app/src/*.c
```

`app/`根目录不得再放 `.c/.h`。公共类型在 `app_types.h`，应用可调参数在 `app_config.h`；模块私有 `static` 常量、变量和函数必须放在对应 `.c` 文件头。

## 3. 功能边界

| 模块 | 只允许做什么 | 明确禁止 |
|---|---|---|
| measurement | 完整DMA块滤波、标定、物理量快照、BAT_I估算 | 发波、保护锁存、充电状态切换 |
| mppt | 更新Vpv_ref并计算理论功率 | 直接改Duty/CCR |
| charger | TC/CC/CV/Float和电池功率上限 | 访问ADC或GPIO |
| protection | 软件阈值、去抖、active/latched故障 | 恢复PWM |
| power_stage | 预充、继电器、Duty目标和状态 | 写寄存器 |
| service | 事件桥接、最终安全复查和驱动提交 | 实现MPPT/充电算法 |
| driver | 外设配置和最小ISR接口 | 包含业务头文件 |

## 4. 自动门禁

`tools/check_architecture.py`拒绝：

- APP包含G32/Board/Driver/Service头文件或访问GPIO、ATMR、DMA、COMP、NVIC；
- Driver反向依赖业务层；
- APP不是 `inc/src` 布局，或Driver/Service/Board出现子目录；
- `legacy_*`、旧闭源库、BAT_S1/BAT_S2、`.bootstrap`、JSON或重复tests/tools；
- APP超过10个 `.c`；
- Service之外直接操作目标PWM寄存器；
- 运行期软件UPDATE、AOE自动恢复或未启用CCR preload；
- 最终PinMap和功率总门被静默修改。

`tools/check_code_style.py`拒绝：

- 函数缺少统一头注释；
- Tab或行尾空白；
- `static`或文件级宏出现在首个公开函数之后；
- 头文件宏没有用途说明；
- APP源码未放入 `inc/src`。
