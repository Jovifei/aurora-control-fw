# 29 · v0.8.1 MCU供电资格修改与验证报告

## 1. 版本目标

v0.8.1解决一个独立于MPPT算法的启动可靠性问题：PV弱光时，MCU辅助电源可能缓慢爬升并在门限附近抖动。如果MCU一退出POR/PDR就立刻初始化IWDT、PWM、COMP、ADC和UART，新增负载和电源扰动可能导致反复复位或长期无法完成启动。

本版本引入 **MCU Supply Qualification**：

> 先把功率相关GPIO置于安全态，再用G32F031 PVD确认VDD连续稳定；只有资格通过后，才进入原v0.8.0完整初始化。

> 路径说明：本报告最初记录的是v0.8.1重构前的文件名；当前两层工程以 `driver/inc/board_config.h`、`driver/inc/drv_system.h` 和 `app/src/main.c` 为准，完整迁移表见 `31-v0.8.3-迁移与验证报告.md`。

这不是新增“MCU弱光保护”。弱光供电不足只表示等待，不生成APP故障、不启动IWDT、不使用PVD中断、不允许PVD系统复位。

设计依据和芯片手册条款见：

- `28-REF-G32F031-MCU供电稳定启动与PVD设计依据.md`
- 《G32F031_M3122_M3114_M3115 数据手册 V1.3》
- 《G32F031_M3122_M3114_M3115 用户手册 V1.3》

## 2. 修改前后对比

### v0.8.0之前

```text
Reset
→ System
→ GPIO
→ IWDT
→ PWM
→ COMP
→ ADC
→ UART
→ APP / Flash
→ ADC DMA
```

缺点：没有确认3.3V MCU供电已经连续稳定。

### v0.8.1

```text
Reset / POR-PDR释放
→ SystemCoreClock + SysTick
→ 最小GPIO安全态
  GLC LOW
  GHC LOW
  Relay OFF
  Link OFF
→ HSI Ready确认
→ PVD配置
→ 等待PVDRDY
→ VDD > VPVD ?
   NO  → 连续稳定计时清0并继续等待
   YES → 连续保持BOARD_MCU_SUPPLY_STABLE_TIME_MS
→ 关闭PVD
→ aurora_runtime_init()
→ IWDT / PWM / COMP / ADC / UART / APP / Flash
→ 原v0.8.0启动、预充、保护、充电、MPPT流程
```

供电资格等待阶段没有总等待超时。清晨或阴天可一直停在安全状态；太阳最终增强后应自动继续初始化，不要求人工重新上电。

## 3. 参数集中化

全部参数位于 `driver/inc/board_config.h`：

```c
BOARD_MCU_PVD_THRESHOLD_MV       = 2800
BOARD_MCU_PVD_FILTER_US          = 50
BOARD_MCU_PVD_READY_TIMEOUT_US   = 1000
BOARD_MCU_SUPPLY_STABLE_TIME_MS  = 100
BOARD_MCU_SUPPLY_CHECK_PERIOD_MS = 1
BOARD_MCU_PVD_RESET_ENABLE       = 0
BOARD_MCU_PVD_IRQ_ENABLE         = 0
```

### 参数意义

| 参数 | 意义 | 当前状态 |
|---|---|---|
| `BOARD_MCU_PVD_THRESHOLD_MV` | PVD名义门限 | 2.8V工程候选，需台架冻结 |
| `BOARD_MCU_PVD_FILTER_US` | PVD内部数字滤波 | 50us候选；映射按复位64MHz HSI |
| `BOARD_MCU_PVD_READY_TIMEOUT_US` | PVD模块建立超时 | 1000us；不是弱光等待超时 |
| `BOARD_MCU_SUPPLY_STABLE_TIME_MS` | VDD连续稳定保持时间 | 100ms，继承旧120W成熟启动思想 |
| `BOARD_MCU_SUPPLY_CHECK_PERIOD_MS` | 软件观察周期 | 1ms |
| `BOARD_MCU_PVD_RESET_ENABLE` | PVD系统复位 | 必须0 |
| `BOARD_MCU_PVD_IRQ_ENABLE` | PVD中断保护 | 必须0 |

目标Driver对最后两个宏设置了编译期`#error`，防止后续误改成1。

## 4. 源码修改

### `driver/inc/board_config.h`

新增PVD门限、滤波、Ready超时、连续稳定时间和“禁止Reset/IRQ”宏。参数都有单位和用途说明。

### `driver/inc/drv_system.h`

新增供电资格接口：

```c
bool drv_system_supply_qualifier_init(void);
bool drv_system_supply_monitor_ready(void);
bool drv_system_supply_is_good(void);
bool drv_system_wait_for_supply_stable(void);
void drv_system_supply_qualifier_stop(void);
```

APP不感知PVD/PMU寄存器。

### `driver/src/drv_system.c`

实现：

1. 确认`HSIRDY`；
2. 显式关闭`PVDRSTEN`；
3. 显式关闭PVD IRQ和上下阈值事件监测；
4. 根据宏选择G32F031 PVD门限；
5. 根据宏选择PVD数字滤波长度；
6. 等待`PVDRDY`；
7. 通过`PVDSTS`读取当前VDD是否高于门限；
8. VDD跌落时连续稳定计时立即清0；
9. 供电连续稳定达到宏配置时间后关闭PVD；
10. 弱光等待不生成Fault、不复位、不启动IWDT。

支持的PVD门限宏值：

```text
2000 / 2400 / 2800 / 3200 / 3600 / 4000 / 4400 / 4800 mV
```

支持的PVD滤波宏值：

```text
1 / 2 / 3 / 5 / 10 / 20 / 30 / 50 us
```

不支持值在编译期直接报错，避免“宏写了一个值但硬件实际落在另一个档位”。

### `app/src/main.c`

当前目标入口在调用`aurora_runtime_init()`之前执行：

```text
drv_system_init
→ drv_io_init
→ Relay/Link/LED安全态
→ drv_system_wait_for_supply_stable
→ aurora_runtime_init
```

因此运行时中的IWDT/PWM/COMP/ADC/UART/APP初始化只能发生在供电资格通过之后；PVD等待期间只保留最小安全GPIO与等待指令。

## 5. 明确没有做的事情

v0.8.1没有：

- 增加`AURORA_FAULT_PVD`；
- 增加`MCU_LOW_VOLTAGE`故障；
- 启用PVD中断；
- 启用PVD系统复位；
- 在弱光等待阶段启动IWDT；
- 改变PV 13V/15V产品启动状态机；
- 改变MPPT算法；
- 改变电池充电/保护参数；
- 改变v0.8.0继电器预充顺序；
- 解锁`BOARD_POWER_OUTPUT_ALLOWED`。

产品协议中原有的`AURORA_FW_VERSION_MAJOR/MINOR/PATCH = 2.0.8`本轮也未擅自修改。它属于产品遥测协议字段，不等同于仓库工程迭代号v0.8.1；若后续需要对外发布固件版本，应另行确认版本策略。

## 6. 自动验证

新增 `tests/test_supply_qualification_contract.py`，固定以下契约：

1. VPVD、滤波、Ready超时、稳定时间全部来自配置宏；
2. HSI Ready检查存在；
3. PVD Reset明确关闭；
4. PVD IRQ明确关闭；
5. PVD Ready和PVD Status均被使用；
6. `System → GPIO安全态 → Supply Qualification → APP运行时完整初始化`顺序不能回退；
7. 完整初始化前不能出现IWDT/PWM/COMP/ADC初始化；
8. VDD跌破门限必须把连续稳定计时清0；

## 7. 必须补做的Keil/台架验证

### 示波器建议

```text
CH1 = MCU VDD
CH2 = NRST
CH3 = PA15 / GLC
CH4 = PA13 / RELAY
```

### 场景

1. MCU供电非常缓慢上升；
2. VDD在2.7~3.3V附近反复抖动；
3. VDD越过门限后在100ms内跌落；
4. VDD最终稳定；
5. 2.8V档与3.2V档在冷热、最低输入和不同负载下对比。

### 必须看到

```text
VDD未连续稳定
→ GLC LOW
→ Relay OFF
→ 无PVD软件Fault
→ 无PVD Reset循环

VDD最终连续稳定
→ 无需重新插拔
→ 自动进入完整初始化
```

并确认供电资格通过以后，原v0.8.0安全链仍然是：

```text
Relay OFF
→ Boost先充BST_U
→ BST_U与BAT_U压差足够小且稳定
→ PWM OFF
→ Service二次实时复核
→ Relay ON
→ 10s BAT_U稳定
→ RUN
```

## 8. 当前安全状态

```c
BOARD_GATE_COMP_ROUTE_VALIDATED = 0
BOARD_GATE_ANALOG_CALIBRATED    = 0
BOARD_GATE_KEIL_LINKED          = 0
BOARD_GATE_LOW_VOLTAGE_BENCH    = 0
BOARD_POWER_OUTPUT_ALLOWED      = 0
```

v0.8.1只解决启动供电资格的软件结构问题，不把Host/CI结果升级成硬件安全结论。

## 9. 结论

v0.8.1建立了明确的两阶段启动模型：

```text
阶段1：MCU自身供电资格
阶段2：产品完整初始化和PV/电池业务
```

弱光只会让阶段1继续等待，不会进入故障死锁或由PVD主动制造复位循环。这一策略与G32F031 PVD能力以及旧120W成熟LVD启动思路相符，最终门限和稳定时间仍需实板波形冻结。
