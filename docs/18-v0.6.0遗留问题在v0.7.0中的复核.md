# 18 · v0.6.0 遗留问题在 v0.7.0 中的复核

## 1. 复核边界

本文件以《32-RPT-v0.6.0修改经验与问题处理总结.md》中记录的问题为输入，对当前 `aurora-control-fw` v0.7.0软件基线逐项复核。旧报告描述的是另一阶段的目录、验证环境和构建产物，不能把旧版PASS/FAIL直接继承为当前版本事实。

## 2. 逐项结论

| P0：自动PinMap存在重复网络 | 使用2026-08-26最终原理图重新建立唯一PinMap；PA8/PV_I、PA9/PV_U、PB0/BAT_U、PB1/BST_U、PA12/LINK、PA13/RELAY、PB10/COMP0_O、PB11/FAULT均唯一；架构门禁固定检查 | **源码/原理图静态冲突已消除**；`BOARD_GATE_PINMAP_REVIEWED=1` | 实物PCB走线、引脚复用和探针点仍需板级核对 |

## 3. v0.7.0新增但仍未关闭的关键风险

### P0

- `BOARD_POWER_OUTPUT_ALLOWED=0`，不可上额定功率；
- COMP0低有效输出到U6 EN以及ATMR Break的物理闭环未强制触发验证；
- NTC标定仍为 `valid=false`，温度通道不能作为已验证放行依据；
- ADC比例、零点、通道顺序和50kHz采样相位未完成板级标定；
- 首次零CCR装载、GLC/Vgs、电感电流与Break后不重发波未抓波形；
- Keil AC6 MAP未生成，不能证明镜像没有进入0xFC00后的Journal区。

### P1

- IWDT实际复位时间未测；
- Flash双页掉电实验未做；
- 12组电池档案仍需逐项对照电芯/BMS规格；
- UART协议需要旧设备Golden Vector；
- MPPT、功率PI、预充阈值需要PV模拟器和限流台架整定。

## 4. 本轮安全决定

本次代码注释、目录和可读性整改不改变任何功率放行条件：

```c
BOARD_GATE_COMP_ROUTE_VALIDATED = 0
BOARD_GATE_ANALOG_CALIBRATED    = 0
BOARD_GATE_KEIL_LINKED          = 0
BOARD_GATE_LOW_VOLTAGE_BENCH    = 0
BOARD_POWER_OUTPUT_ALLOWED      = 0
```

因此v0.7.0仍是“可审计、可Host验证的软件候选基线”，不是完成板级验收的量产固件。
